# t-WiKi

로컬 폴더 하나를 그대로 위키로 쓰는 마크다운 지식 기반 앱입니다.
빌드 결과물은 정적 HTML/JS/CSS 뿐이라 아무 정적 호스팅에나 올리면 되고, 서버는 필요 없습니다.

- 문서는 **평범한 `.md` 파일**로 내 PC 폴더에 저장됩니다. 옵시디안이나 다른 편집기로 같은 폴더를 열어도 됩니다.
- 폴더 구조가 곧 문서 구조입니다. 트리에서 만들고, 이름 바꾸고, 끌어다 옮깁니다.
- `[[문서 이름]]` 위키 링크와 백링크를 지원합니다. 없는 문서는 클릭해서 바로 만듭니다.
- 코드 하이라이팅, mermaid 다이어그램, 수식, 콜아웃, 각주, 목차를 렌더합니다.
- 테마와 글꼴을 골라 쓸 수 있습니다.
- 이미지·PDF 같은 **첨부 파일도 함께 동기화**합니다. 고르면 읽기 전용으로 미리 봅니다.
  압축(`.zip` `.rar` `.7z` `.alz`)도 받고, zip 은 풀지 않고 **안엣것 목록**을 보여 줍니다.
> 양쪽에서 같은 문서를 즐겨찾기에 넣고 각자 동기화하면 그 파일도 부딪힙니다.
> 다른 문서와 똑같이 충돌 정책을 따릅니다(기본은 양쪽 다 보존).

- 지정한 **GitHub 저장소와 양방향 동기화**합니다. 저장 이력이 커밋으로 남습니다.
  커밋 글은 첫 줄에 `t-WiKi: 추가 2건, 수정 1건, 삭제 1건` 처럼 세어 두고,
  그 아래에 갈래별로 어떤 경로였는지 적습니다. 첨부도 함께 셉니다.

> **쓰는 법은 [USAGES.md](USAGES.md) 에 따로 있습니다.**
> 무엇을 눌러 어떻게 하는지, 설정 항목이 무슨 뜻인지, 막혔을 때 무엇을 볼지가 거기 있습니다.
> 이 문서는 **무엇을 만들었고 왜 그렇게 했는지**를 적는 기록입니다 — 기능과 그 설계,
> 개발과 배포. 그래서 같은 기능이라도 여기서는 *까닭*을, 저기서는 *절차*를 읽게 됩니다.

## 필요 환경

- **Chromium 계열 데스크톱 브라우저** (Chrome, Edge, Arc, Brave 등)
  File System Access API 를 쓰기 때문입니다. Firefox 와 Safari 에서는 폴더를 열 수 없습니다.
- 페이지가 **`https://`** 또는 **`http://localhost`** 로 열려야 합니다.
  `file://` 로 연 HTML 은 opaque origin 이라 `showDirectoryPicker()` 가 `SecurityError` 로 거부되고,
  blob SHA 계산에 쓰는 `crypto.subtle` 도 보안 컨텍스트에서만 동작합니다.

## 개발

소스는 <https://github.com/taknim/t-wiki> 에 있습니다. 내려받아 그대로 띄우면 됩니다.

```bash
git clone https://github.com/taknim/t-wiki.git
cd t-wiki
npm install
npm run dev      # http://localhost:5173
npm run build    # dist/ 에 정적 결과물 생성
npm run preview  # 빌드 결과 확인
npm run lint
```

## 좁은 화면(손전화)

720px 보다 좁으면 옆줄이 본문 옆이 아니라 **본문 위에 서랍처럼** 뜹니다. 옆줄이 화면을
반 넘게 먹어 본문이 몇 글자씩 끊기던 것을 없애려는 것입니다.

- 처음에는 닫힌 채 시작합니다. 열어 둔 채 시작하면 본문이 보이지 않아 무엇이 열렸는지 알 수 없습니다.
- 머리줄 왼쪽 끝의 **≡ 메뉴 단추**로 엽니다. 넓은 화면에서는 이 단추가 없고 옆줄 자체의 접기·펴기 단추를 씁니다.
- 서랍은 화면보다 조금 좁아(최대 360px) 뒤의 본문이 비치고, 반투명 덮개가 깔립니다.
  **문서를 고르면 저절로 닫히고**, 폴더를 골랐을 때는 그 안을 더 둘러보려는 것이라 열린 채 둡니다.
  덮개를 누르거나 옆줄의 접기 단추로도 닫힙니다.
- 머리줄 단추(동기화·단축키·설정)는 아이콘만 남깁니다.
- 나란히 보기는 원문과 결과가 **위아래로** 서고, 사이의 손잡이도 함께 눕습니다. 넓은 화면에서
  좌우 몫을 정하듯 **위아래로 끌어** 몫을 정하고, 두 번 누르면 반반, 자판으로는 `↑↓`
  (넓을 때는 `←→`)입니다. 몫은 넓을 때와 같은 값을 쓰므로 창을 늘이고 줄여도 이어집니다.
- 설정 창의 왼쪽 메뉴는 **감춥니다.** 위로 눕혀 두었더니 창의 반을 메뉴가 먹어 정작 설정이
  몇 줄 안 보였습니다. 본문에 같은 머리가 차례로 서 있으니 굴려서 찾으면 됩니다.
- **손을 얹을 수 없는 기기(hover 없음)** 에서는 줄 오른쪽 단추가 영영 안 보이므로, **고른 줄에서는
  늘 보이게** 둡니다 — 눌러 고르고 나서 단추를 씁니다. 안내 말풍선은 손가락에 가려 방해만 되어 띄우지 않습니다.
- **손가락으로는 끌어다 옮길 수 없습니다.** 손전화 브라우저는 손가락으로 시작한 끌기를 HTML 끌어놓기로
  올려 주지 않습니다. 대신 줄 단추의 **옮기기**(폴더에 화살표)를 누르면 옮겨 갈 폴더를 고르는 창이 뜹니다.
  폴더 자신과 그 아래, 지금 있는 자리는 고를 수 없습니다. 같은 이름이 있으면 끌어다 놓을 때처럼 덮을지 묻습니다.
- **옮기기 전에 한 번 묻습니다**(어디서 → 어디로). 끌어다 놓든 폴더를 고르든 같습니다. 끌다가 엉뚱한
  폴더에 놓는 일이 잦고, 옮기고 나면 어디로 갔는지 찾아야 하기 때문입니다. 같은 이름이 있을 때는
  덮을지 묻는 창 하나로 갈음해 두 번 묻지 않습니다.
  창은 **지금 있는 자리가 가운데에 오도록 굴린 채** 뜹니다 — 폴더가 많으면 어디서 옮기는지부터 찾아야 했습니다.
  그 줄은 고를 수 없어 흐려지는데 그러면 도리어 눈에 안 띄어, 트리의 고른 줄과 같은 음영에 테두리를 둘러 먼저 보이게 합니다.
  이 단추는 넓은 화면에도 있어 자판만 쓰는 사람도 옮길 수 있습니다.

> 이 앱은 File System Access API 가 있어야 폴더를 엽니다. 손전화의 크롬은 그것이 없어 첫 화면에서
> 멈추므로, 이 배치는 태블릿·데스크톱 모드의 좁은 창이나 화면을 나눠 쓸 때를 위한 것입니다.

## 단축키

목록은 코드의 표(`src/lib/shortcuts.ts`)를 그대로 그리므로 **코드와 어긋나지 않습니다.**
새 단축키는 그 표에만 더하면 목록 창까지 따라옵니다.
상단 **단축키** 단추나 `⌘/` 로 뜨고, 덮개도 닫기 단추도 없이 다른 곳을 누르면 걷힙니다.
자리와 너비는 **그때그때 화면 폭에 맞춰** 잡습니다 — 단추 오른쪽에 그냥 맞춰 두면 좁은 화면에서
왼쪽이 화면 밖으로 잘리므로, 가장자리 안쪽으로 밀고 너비도 화면 안에서 정합니다.

→ 어떤 글쇠가 무엇을 하는지는 [USAGES.md 의 단축키](USAGES.md#단축키).

**브라우저가 먼저 가져가는 글쇠는 쓰지 않습니다.** `⌘N`·`⌘⇧N` 은 새 창·시크릿 창이라 페이지까지
오지 않아 새 문서를 `⌘⇧D` 로 두었고, `⌘⇧J`·`⌘⇧C`·`⌘⇧I` 는 개발자 도구, `⌘⇧O` 는 북마크,
`⌘⇧R` 은 새로 고침, `⌘G` 는 "다음 찾기" 입니다. 그래서 행으로 가기는 `⌘⇧L`(line)이고,
줄 번호·커서 위치의 `K`·`Y` 도 남은 글쇠 가운데 고른 것이라 글자에 큰 뜻은 없습니다.
편집기 안의 `⌘E`·`⌘B` 와 전역 `⌘⇧E`·`⌘⇧B` 는 Shift 로 갈립니다 — 편집기는 ⇧·⌥ 가 붙은
글쇠를 서식으로 받지 않습니다.

**옆줄은 자판만으로 오갈 수 있습니다.** 검색 칸에서 `↓` 를 누르면 결과가, 검색어가 없으면
폴더 트리(또는 즐겨찾기)에서 **지금 열어 둔 줄**이 잡힙니다 — 맨 위에서 시작하면 열어 둔
문서까지 한 줄씩 내려가야 해서 어색합니다. 열어 둔 것이 없으면 첫 줄입니다. 폴더는 고르고,
고른 폴더에서 다시 `Enter` 를 누르면 펴고 접습니다(마우스와 같은 규칙). 파일이나 접힌
폴더에서 `←` 는 부모 폴더로 올라가고, 맨 위에서 `↑` 는 검색 칸으로 돌아갑니다.
고른 줄만 Tab 차례에 들어 있어 Tab 을 수백 번 누를 일이 없습니다.

## 설정

상단 ⚙ 를 누르면 설정이 열립니다. 내용은 **한 페이지**로 이어져 있고,
왼쪽 메뉴는 **묶음과 그 안의 갈래**로 갈라져 있습니다.
*일반 · 모양 · GitHub 동기화* 아래에 그 묶음의 갈래가 한 칸 들여 늘어섭니다.
어느 쪽을 눌러도 그 자리로 곧바로 갑니다. 설정이 늘면서 묶음 셋만으로는 굴려
찾아야 했습니다. 지금 보고 있는 줄은 굴릴 때마다 저절로 짙어집니다.

| 묶음 | 갈래 | 그 안에 든 설정 |
| --- | --- | --- |
| 일반 | 마지막 화면 상태 · **미리보기** · 저장할 때 정돈 · 휴지통 · 설정 주고받기 | 미리보기 = 이미지 + 오피스, 휴지통 = 저절로 비우기 + 날수 |
| 모양 | 테마 · **본문** · **이미지** · 편집기 | 테마 = 테마 + 밝기, 본문 = 글꼴·크기·줄 간격·너비, 이미지 = 정렬 + 최대 너비, 편집기 = 줄 번호 + 커서 위치 |
| GitHub 동기화 | **저장소 연결** · **동기화 방식** · 동기화 실행 · 이 폴더의 설정 | 연결 = 토큰 + 저장소·브랜치, 방식 = 충돌 처리 + 자동 동기화 |

**갈래는 설정 하나가 아니라 한 갈래에 드는 설정 몇 개를 가리킵니다.** 설정마다 한 줄씩
세우면 메뉴가 화면보다 길어져, 목록을 굴려 찾던 처음으로 돌아갑니다.

**본문도 메뉴와 똑같이 묶여 있습니다.** 갈래 이름이 본문에 머리로 서고 그 아래에
설정이 모입니다. 머리줄은 굴려도 제자리에 있습니다.
본문 끝에는 **마지막 갈래가 위쪽까지 올라올 만큼의 빈 자리**를 둡니다.
그것이 없으면 마지막 갈래는 굴림이 끝에 닿아 있어, 눌러도 화면이 꿈쩍하지 않습니다.
한 화면을 통째로 비우지는 않습니다. 메뉴에서만 묶고 본문은 늘어놓으면, 눌러서 온 자리에 그 이름이
어디에도 없어 제대로 왔는지 알 수 없습니다. 굴리는 동안 지금 보고 있는 갈래가
왼쪽에서 계속 짙게 남습니다.

**묶음 이름은 트리의 폴더 줄과 같은 규칙으로 움직입니다.** 처음 누르면 그 자리로 가고,
**이미 보고 있는 묶음을 다시 누르면 접힙니다.** 접힌 묶음은 누르면 펴지면서 그 자리로
갑니다. 누를 때마다 접혔다 펴지게 하면 옆 묶음으로 건너가려던 사람이 번번이 목록을
잃습니다. 접어 둔 것은 창을 닫으면 잊습니다 — 잠깐 들르는 자리라, 접어 둔 줄 모르는
사람에게는 설정이 사라진 것처럼 보이기 때문입니다.
직접 스크롤해도 메뉴 강조가 따라옵니다. 모양 설정은 고르는 즉시 적용됩니다.

**닫을 때 보던 갈래를 기억했다가 다음에 그 자리에서 엽니다.** 설정은 잠깐 들러 고치고
닫는 자리라, 다시 열 때 보던 갈래가 그대로 나오면 이어서 손볼 수 있고 매번 맨 위에서
굴려 내려가지 않아도 됩니다. 닫는 길(단추 · 바깥 누르기 · Esc)이 무엇이든 적어 둡니다.
갈 곳이 정해진 부름은 이 기억보다 앞섭니다 — 동기화 설정이 덜 된 채 **GitHub 동기화**를
누르면 기억과 상관없이 그 묶음으로 갑니다. 저장해 둔 이름이 지금 판에 없으면(갈래를 고쳐
이름이 바뀐 뒤) 맨 위에서 엽니다. 이 책갈피는 취향이 아니라 설정 파일에는 담지 않습니다.

- **뒷 화면을 어둡게 덮지 않습니다.** 색과 글꼴을 고르는 동안 화면이 어떻게 바뀌는지
  그대로 보여야 하기 때문입니다. 대신 그 자리를 덮고 있어 뒤쪽은 눌리지 않습니다.
- **머리줄을 잡아 끌면 창이 옮겨집니다.** 가려진 곳을 보면서 고칠 수 있습니다.
  어느 쪽으로 끌어도 80px 은 화면에 남고, 머리줄은 위로 사라지지 않습니다.
  다시 열면 가운데에서 시작합니다.
- **Esc 를 누르거나 바깥을 클릭하면 닫힙니다.** 창이 겹쳐 떠 있으면 **맨 위 하나만**
  닫힙니다. 설정 위에 동기화 결과가 떠 있으면 결과가 먼저, 그 위에 확인 창이 있으면
  확인 창이 먼저입니다. 아래 것이 먼저 닫히면 위에 남은 창이 무엇에 딸린 것인지
  알 수 없게 됩니다. 확인 창의 *취소* 는 전부터 (Esc) 라고 적어 두었고, 이제 실제로도
  그렇게 동작합니다.

### 자동 저장 (일반)

**손을 멈추고 얼마 뒤에 파일에 쓸지** 정합니다. 기본은 켜짐, 0.8초입니다.

- 초는 0.1 ~ 60 초. 0.1 초 아래로는 치는 도중에 쓰게 되고, 1분을 넘기면 자동이라 부를 수 없습니다.
- **기다리는 동안 제목 옆에 남은 시간이 적힙니다**(`3초 뒤 자동 저장`). 곁에 선 **저장** 단추를
  누르면 기다리지 않고 바로 씁니다. 단추는 자동 저장이 켜져 있어도 나옵니다 — 지금 쓰고 싶을
  때가 있기 때문입니다.
- **끄면** `변경됨` 이라고 적히고, 저장은 그 단추나 `⌘S`, 그리고 문서를 떠날 때만 일어납니다.
- **문서를 옮기면 셈을 처음부터 다시 잡습니다.** 떠나는 길에 앞 문서는 이미 저장되므로,
  새 문서에는 남은 시간이 아니라 온전한 시간이 주어져야 합니다.
- **꺼 두었을 때 다른 문서·폴더로 옮기려 하면 묻습니다** — *저장하지 않고 이동* 과 *취소*.
  물러서면 아무 데도 가지 않으므로 저장 단추를 누를 기회가 그대로 남고, 창에도 그렇게 적어
  둡니다("저장이 필요하면 취소를 누르고 저장 단추로 저장한 뒤 옮겨 가세요"). 말없이 쓰면
  "내가 누를 때만 쓴다"는 약속을 깨는 것이고, 말없이 버리면 고친 것을 잃습니다.
  켜 두었을 때는 예전처럼 묻지 않고 쓰고 갑니다 — 어차피 곧 쓸 것이기 때문입니다.
- **파일에 쓰는 동안에는 편집기가 잠깁니다**(제목 옆에 `저장 중…`). 그 사이에 친 글자는
  방금 파일에 담은 것과 어긋나고, 곧이어 돌아오는 저장 결과에 덮여 소리 없이 사라집니다.
  잠그는 것은 `disabled` 가 아니라 `readOnly` 입니다 — 커서와 선택, 굴려 둔 자리를 잃지
  않아야 다 쓰고 나서 하던 자리에서 이어 칠 수 있습니다. 미리보기의 할 일 네모도 같이 막습니다.
  보통은 눈에 띄지 않을 만큼 짧고, 큰 파일이나 느린 기기에서만 잠깐 보입니다.
- 동기화는 **어느 쪽이든** 돌기 전에 편집 중이던 것을 먼저 저장합니다. 반쯤 쓴 글이 올라가는
  것보다 낫습니다.

저장 단추는 **말 앞에**, 글자 없이 **아이콘만** 섭니다. 곁의 말이 이미 글자라 거기에 글자를
더하면 어느 쪽이 눌리는 것인지 되레 헷갈립니다. 색도 입히지 않습니다(다른 단추와 같은 기본
모양) — 눈에 걸려야 하는 것은 단추가 아니라 **"아직 안 들어갔다"는 말**이기 때문입니다.
그 말에는 알림색(`--warn`)을 입히고 테두리까지 같은 색으로 물들입니다. 흐린 글씨로 두었더니
`저장됨` 에서 `변경됨` 으로 바뀐 것이 눈에 띄지 않았습니다.
꺼 두었을 때 적는 말은 `저장 안 함` 이 아니라 **`변경됨`** 입니다 — 앞의 말은
앞으로도 저장하지 않겠다는 뜻으로 읽히지만, 실제로 알려야 하는 것은 "고친 것이 아직 파일에
들어가지 않았다" 는 지금의 상태입니다.

제목 옆의 표시는 예전에 `저장 중…` / `저장됨` 두 마디뿐이었습니다. 자동 저장을 끌 수 있게
되면서 그 말로는 모자랍니다 — 꺼 둔 채 `저장 중…` 이라고 적으면 저절로 써 줄 것처럼 읽힙니다.

### 마지막 화면 상태 기억 (일반)

**폴더를 다시 열면 마지막 상태로 되돌립니다.** 기본으로 켜져 있습니다.

- 펼쳐 두었던 폴더와 마지막으로 고른 문서·첨부·폴더를 기억합니다
- **보기 모드(편집 · 나란히 · 미리보기)도 폴더마다 따로 기억합니다.** 미리보기로 보던
  중에 새로고침해도 나란히로 되돌아가지 않습니다
- 새로고침하거나, 폴더를 닫았다가 나중에 다시 열어도 그대로 이어집니다
- 폴더는 **이름이 아니라 실제 위치로 구분**하므로 같은 이름의 다른 폴더와 섞이지 않습니다
- 최근 연 폴더 10개까지 기억하고 그보다 오래된 것은 버립니다
- **기억한 상태 지우기** 로 한 번에 비울 수 있습니다

이 기록은 이 브라우저에만 남고 저장소로 올라가지 않습니다.

### 이미지 미리보기 (일반)

**고른 이미지를 화면에 그릴지** 정합니다. 기본은 켜짐입니다.

- 끄면 트리에서 이미지를 골라도 그림 대신 안내 한 줄만 나옵니다.
  파일을 **읽지도 않으므로** 큰 그림이 많은 폴더에서 쓸모가 있습니다
- 안내에는 다시 켜는 길(설정 → 일반 → 이미지 미리보기)이 함께 적힙니다
- **문서 안에 넣은 그림(`![](…)`, `![[…]]`)은 이 설정과 상관없이 그대로 나옵니다.**
  본문의 일부라 빼면 글이 끊깁니다. 여기서 다루는 것은 이미지 파일 자체를 골랐을 때뿐입니다
- 어느 쪽이든 파일은 그대로 폴더에 있고, 동기화에도 영향이 없습니다

폴더가 아니라 **이 브라우저의 취향**이라 폴더를 바꿔도 그대로 따라옵니다.
설정 주고받기로 내보내면 다른 기기로도 옮겨집니다.

### 오피스 미리보기 (일반)

**워드·엑셀을 화면에 그릴지** 정합니다. 기본은 켜짐입니다.

- 끄면 파일을 **읽지도, 읽는 벌을 내려받지도 않고** 안내 한 줄만 나옵니다.
  그 벌이 작지 않아, 열 때마다 받는 것이 달갑지 않다면 꺼 둡니다
- 안내에는 다시 켜는 길(설정 → 일반 → 오피스 미리보기)이 함께 적힙니다
- 어느 쪽이든 파일은 그대로 폴더에 있고, 동기화에도 영향이 없습니다

### 그림 뒤에 깔 바탕

투명한 그림이나 화면과 색이 비슷한 그림은 바탕에 묻혀 보이지 않습니다.
흰 로고는 밝은 테마에서, 어두운 도표는 어두운 테마에서 사라집니다.
그래서 이미지를 고르면 **제목 줄 오른쪽 끝**에 배경을 고르는 단추가 섭니다.
문서의 보기 모드와 같은 자리, 같은 모양입니다.
앞에 **배경** 이라고 적어 두고, **단추마다 제가 깔 색을 그대로 입습니다.**
그 위의 글자는 바탕에 맞춰 색이 갈리므로, 테마가 바뀌어도 묻히지 않습니다
(모두 4.5:1 이상). 고른 단추는 바탕을 덧칠할 수 없어 안쪽에 강조색 테를 두르고
글자를 굵게 합니다.

| | |
| --- | --- |
| **기존** (기본) | 손대지 않은 본디 바탕. 지금 테마의 색을 그대로 씁니다 |
| **밝게** | 흰 바탕에 놓고 봅니다. 어두운 그림에 씁니다 |
| **중간** | 밝지도 어둡지도 않은 회색. 양쪽 다 아닌 그림에 씁니다 |
| **어둡게** | 어두운 바탕에 놓고 봅니다. 흰 로고처럼 밝은 그림에 씁니다 |

밝게·중간·어둡게는 **테마를 따르지 않는 고정된 색**입니다. 테마를 따르게 하면
테마와 색이 비슷해 묻히는 그림을 살릴 수 없어, 애초에 이 자리를 만든 뜻이 사라집니다.
고른 것은 이 브라우저에 기억되고 설정 꾸러미에도 함께 담깁니다.

고른 바탕은 **여백도 테두리도 없이 칸을 가득 채웁니다.** 가장자리에 다른 색이 남으면
어느 것이 고른 바탕인지 헷갈립니다. 대신 **그림 자체에 테두리**를 둘렀습니다.
어두운 금과 밝은 테를 겹쳐 둘러, 네 바탕 어느 쪽에서도 그림의 끝이 보입니다.
투명한 그림은 이 테두리가 있어야 어디까지가 그림인지 알 수 있습니다.

칸 오른쪽 위에 크기가 붙습니다. 궁금한 것이 둘이라 둘 다 적습니다 —
**지금 눈에 보이는 크기**와 **파일이 지닌 크기**.

```
936 × 234px
원본 2000 × 500px · 47%
```

줄지 않고 제 크기로 그려진 그림에는 윗줄만 적습니다. 같은 숫자를 두 번 적으면
되레 읽기 나쁩니다. 창을 늘이거나 이미지 최대 너비를 바꾸면 윗줄과 몫이 함께 따라옵니다.
크기를 밝히지 않은 SVG 에는 붙지 않습니다.

### 테마

| 이름 | 성격 |
| --- | --- |
| 기본 | 중립적인 회색과 파랑 |
| 깃허브 | GitHub 문서와 같은 색 |
| 세피아 | 오래 읽기 좋은 따뜻한 종이색 |
| 먹 | 검은 먹과 인장 붉은색, 군더더기 없는 흑백 |
| 고대비 | 흑백을 끝까지 밀어붙인 배색, 눈이 편치 않을 때 |
| 그루비박스 | 흙빛 종이에 진한 색, 복고풍 배색 |
| 감귤 | 크림빛 종이에 잘 익은 주황, 환한 화면 |
| 에스프레소 | 볶은 원두빛 짙은 갈색, 밤에도 따뜻하게 |
| 장미 | 따뜻한 분홍과 자주, 부드러운 인상 |
| 숲 | 이끼와 잎사귀, 초록이 도는 화면 |
| 바다 | 청록빛 물색, 서늘하고 맑은 화면 |
| 포도 | 보랏빛이 감도는 차분한 화면 |
| 노르드 | 차분한 한랭 계열 |
| 솔라라이즈드 | 눈부심을 줄인 고전 배색 |
| 드라큘라 | 어두운 바탕에 형광빛, 가장 또렷한 대비 |

테마마다 밝은 배색과 어두운 배색을 따로 갖고 있습니다.
**색은 눈으로만 고르지 않습니다.** 스무 가지 색을 바탕과 견주어 대비비를 재고,
본문 글자는 4.5:1, 흐린 글자·강조색·상태색은 3:1 을 넘게 잡았습니다.
코드 색만 2.5:1 로 조금 낮춥니다. 주석은 물러서 있어야 하는 색입니다.
이 잣대는 `tests/suites/theme-check.mts` 가 지킵니다.
**코드 하이라이팅과 mermaid 다이어그램 색도 고른 테마를 따라갑니다** —
다이어그램은 내장 테마 대신 앱 색을 직접 넘겨서 그리므로 문서와 따로 놀지 않습니다.

### 밝기

`시스템 따름` / `밝게` / `어둡게` 중에 고릅니다.
`시스템 따름` 일 때만 운영체제 설정을 따라가고, 나머지는 시스템과 무관하게 고정됩니다.

### 타이포그래피

- **본문 글꼴** — 산세리프 / 세리프 / 고정폭. 미리보기 본문에만 적용되고 편집기는 고정폭을 유지합니다.
  **세리프는 한글도 명조로 바뀝니다.** 글꼴 벌은 글자마다 앞에서부터 그 글자를 가진 첫 벌을
  쓰므로, 한글 자리에 고딕이 먼저 서 있으면 이름만 세리프이고 한글은 그대로입니다.
  한글 명조(Apple 명조 · 본명조 · 나눔명조 · 바탕)를 라틴 세리프 바로 뒤에 세워 두었습니다.
- **글자 크기** — 아주 작게(13px) / 작게(14px) / 보통(15px) / 크게(17px) / 아주 크게(19px)
- **줄 간격** — 아주 좁게(1.3) / 좁게(1.5) / 보통(1.7) / 넓게(1.9) / 아주 넓게(2.2).
  빽빽한 표를 볼 때와 긴 글을 읽을 때 알맞은 간격이 달라 다섯 단계로 나눠 두었습니다.
  **미리보기와 편집기에 함께 걸립니다.**
  읽는 쪽과 쓰는 쪽이 따로 놀면 어지럽습니다. 첨부의 글 미리보기도 같이 따릅니다.
  배수라서 글자 크기를 바꿔도 비율은 그대로입니다.
- **본문 너비** — 좁게(680px) / 보통(1000px) / 넓게(제한 없음).
  좁게·보통은 글줄이 길어지지 않도록 폭만 묶습니다. 자리는 왼쪽 끝 그대로입니다.
  **표와 코드 블록도 같은 폭에 섭니다.** 그 둘만 창 끝까지 늘이면 왼쪽만 맞고
  오른쪽이 어긋나 글이 들쭉날쭉해 보입니다. 넘치는 것은 잘리지 않고
  제 칸 안에서 옆으로 굴러갑니다.
  두 값은 코드 줄을 잣대로 잡았습니다. 기본 글자 크기에서 코드 글씨는 13.5px
  고정폭이라, **좁게는 80칸, 보통은 120칸** 한 줄이 들어옵니다.
  한글로 치면 45자와 66자쯤입니다. 좁게는 글만 읽는 자리, 보통은 표와 코드가 섞인
  문서를 펴 놓는 자리로 봅니다.
  **표는 같은 너비에 섭니다.** 다만 **코드만 보는 칸은 쪽 전체**를 씁니다 — 글줄 폭에 묶어
  두었더니 마크다운 문서의 한 문단처럼 보여, 파일을 보고 있다는 느낌이 들지 않았습니다.
  글꼴·글자 크기·줄 간격도 함께 따릅니다. 같은 설정을 두고 화면마다 다르게 보이면
  설정을 믿을 수 없게 됩니다. 코드와 표의 글씨는 본문의 0.9배로, 크기를 바꾸면
  함께 움직입니다.
- **이미지 정렬** — 왼쪽(기본) / 가운데 / 오른쪽.
  한 줄을 통째로 차지하는 그림만 세웁니다. 글줄에 섞여 흐르는 그림까지 옮기면
  그 문단의 글자가 함께 밀려납니다. 문서 안의 그림과 **그림 파일 미리보기**에
  같이 걸립니다.
- **이미지 최대 너비** — 제한 없음(기본) / 크게(720px) / 보통(520px) / 작게(320px).
  **큰 그림만 줄이고 작은 그림은 늘리지 않습니다.** 본문 너비보다 커지는 일도 없어,
  둘 가운데 좁은 쪽을 씁니다.

설정은 `localStorage` 에 저장됩니다.
다른 설정처럼 IndexedDB 에 두면 읽기가 비동기라 첫 화면이 잠깐 기본 테마로 번쩍이기 때문입니다.

## 서식 도구

편집기에서 글자를 선택하면 그 자리에 도구 막대가 뜹니다.
같은 버튼을 다시 누르면 서식이 풀립니다.

| 묶음 | 버튼 |
| --- | --- |
| 글자 | 굵게 · 기울임 · 취소선 · 인라인 코드 |
| 제목 | H1 · H2 · H3 |
| 목록 | 글머리 · 번호 · 체크박스 · 인용 |
| 삽입 | 링크 · 위키링크 · 코드 블록 · 수식 |

- **여러 줄을 선택하면** 목록·인용·제목은 걸친 모든 줄에 적용됩니다.
  번호 목록은 1부터 다시 매기고, 이미 다른 종류의 목록이면 갈아탑니다.
- **줄 가운데만 선택해도** 줄 단위 서식은 그 줄 전체에 걸립니다.
- **아무것도 선택하지 않고** 단축키를 누르면 예시 문구가 들어가고 그 부분이 선택됩니다.
- 링크는 선택한 글자가 라벨이 되고 주소 자리에 커서가 갑니다.
  선택한 것이 주소처럼 생겼으면 반대로 라벨 자리를 선택해 줍니다.

### 수식

문장 안에는 `$E = mc^2$`, 문단 하나를 차지하는 수식은 `$$ ... $$` 로 씁니다.
**블록 수식은 줄 첫머리의 `$$` 에서만 시작합니다.** 줄 가운데의 `$$` 까지 가리키면, 수식 쓰는
법을 글로 설명하느라 문장 안에 `$$` 를 적어 두기만 해도 거기서 문단이 끊기고 블록 수식이 그
뒤의 코드 울타리를 통째로 삼켜, **문서의 나머지가 통째로 어긋났습니다**(설명서를 쓰다 걸렸습니다).
KaTeX 로 조판하고 스크린리더용 MathML 도 함께 냅니다.
`\$` 로 쓰면 그냥 달러 기호이고, `$5 와 $10` 처럼 여는 기호 뒤에 공백이 오는 경우도 수식으로 잡지 않습니다.

### 편집기의 줄 번호와 커서 위치

둘 다 **설정 → 모양 → 편집기**에서 켭니다. 기본은 꺼짐입니다. 모든 글 문서의 편집 화면에 같이 걸립니다.

- **줄 번호**는 편집 화면 왼쪽에 섭니다. 글상자는 줄 번호를 세워 주지 않고 긴 줄은 접혀 두세
  줄로 그려지므로, 번호 하나가 몇 픽셀인지 미리 알 수 없습니다. 글상자와 같은 글꼴·폭·접기로
  그린 **보이지 않는 거울**에 줄마다 한 덩이씩 놓고 그 높이를 재서 번호를 같은 높이로 세웁니다.
  그래서 접힌 줄 옆에도 번호는 한 번만, 그 줄 전체 높이로 섭니다. 긴 줄을 접지 않고 옆으로
  굴리는 길도 있지만 산문에는 맞지 않아 택하지 않았습니다. 굴리면 번호도 함께 굴러갑니다.
  창 폭이 바뀔 때는 물론, **줄 간격 설정을 바꿀 때도 다시 잽니다** — 줄 간격은 CSS 변수로만 바뀌어
  편집기가 알 길이 없으므로 거울의 첫 줄 높이를 지켜보다가 달라지면 다시 잽니다.
- **커서 위치**는 아래 표시줄 오른쪽, 크기 앞에 `행 12 열 5` 로 적힙니다. 행은 줄바꿈으로,
  열은 그 줄 안의 글자 수로 셉니다(둘 다 1부터). 미리보기만 볼 때처럼 편집기가 없으면 나오지 않습니다.
- 그 표시를 **누르면 갈 자리를 묻습니다** — 행과 열을 **칸마다 따로**(지금 자리가 미리 적혀 있음).
  열을 비우면 그 줄 첫 칸. 커서를 옮기고 목차처럼 그 줄이 위쪽에 오게 굴립니다. 줄 수를 넘는 행은
  마지막 줄로, 줄 길이를 넘는 열은 줄 끝으로 접습니다 — 어림잡아 큰 수를 적어도 거절하지 않고 가장
  가까운 곳에 세웁니다. 옮기는 일은 물음 창이 닫힌 한 박자 뒤에 합니다. Enter 의 keydown 에서 창이
  닫히는데 그 자리에서 곧장 편집기에 초점을 주면 같은 Enter 의 keypress 가 편집기로 새어 들어 줄바꿈을
  끼워 넣었습니다.
- 번호 칸은 틀 위에 띄워 둡니다. 흐름에 두면 번호 수백 줄의 높이가 틀의 크기로 잡혀 틀이 글상자보다
  길어지고, 그러면 글상자 대신 본문 칸 전체가 굴러갔습니다. 띄우면 틀의 크기는 글상자만으로 정해집니다.
  거울도 높이를 0 으로 눌러 둡니다 — 띄워 둔 것이라 흐름에는 안 끼지만 아래로 삐져나온 만큼은 본문
  칸의 굴림 범위에 들어가, 굴림대가 둘이 되고 화면이 아래로 넘어갔습니다.
- 두 값은 모양 설정의 한 벌이라 설정 파일에 함께 담깁니다.

### 코드 울타리를 세는 법

문서를 훑어 제목과 할 일을 찾을 때는 코드 블록 안을 건너뜁니다. 그런데 울타리를 만날 때마다
안팎을 뒤집기만 했더니 **울타리 안의 울타리**에서 어긋났습니다 — 코드 블록 쓰는 법을 글로
보이려면 바깥을 백틱 넷으로 두르고 안에 셋을 적는데, 안쪽 셋을 닫는 것으로 세어 그 뒤가 통째로
밀렸습니다. 목차에 코드 안의 제목이 들어오거나 뒤의 제목이 빠지고, 미리보기의 할 일 네모도
엉뚱한 줄을 켰습니다. 지금은 규격대로 **같은 글자에 길이가 같거나 더 긴 울타리**만 닫는 것으로
봅니다(사용 설명서를 쓰다 걸린 일입니다).

### 목차와 앵커

제목마다 앵커가 생기고, 본문 오른쪽 아래 **목차** 단추로 목록을 펼칩니다(제목이 둘
이상일 때). 제목에 마우스를 올리면 `#` 링크가 보입니다.

**편집만 보고 있을 때도 목차로 그 줄을 찾아갑니다.** 결과 화면이 없어 뛰어갈 앵커가
없으므로, 제목이 시작하는 **글자 자리**를 짚어 편집기에 커서를 세우고 그 줄이 위쪽에
오도록 굴려 줍니다. 얼마나 굴려야 하는지는 서식 도구가 쓰는 것과 같은 **보이지 않는 사본**에서
그 글자의 세로 자리를 재서 정합니다. 예전에는 그 자리까지의 글만 잠깐 담아 `scrollHeight` 를
재고 되돌렸는데, 내용이 칸보다 짧으면 `scrollHeight` 가 칸 높이로 눌려 앞쪽 줄로 가자는데도
아래로 굴러갔습니다.
제목은 앞머리(frontmatter)를 뗀 본문에서 뽑으므로 — 앞머리 안의 `# 메모` 같은 줄까지
제목으로 셀 수는 없습니다 — 편집기로 뛸 때는 **뗀 만큼 자리를 밀어** 줍니다.

### 할 일 목록

`- [ ] 할 일` / `- [x] 끝낸 일` 로 적으면 네모가 그려지고, **미리보기에서 눌러서 켜고
끕니다.** 누르면 원문의 그 줄이 `[ ]` ↔ `[x]` 로 바뀌고, 늘 하던 대로 자동 저장이
이어받습니다. 나란히 보기라면 편집기에도 바로 비칩니다.

- `- [ ]`, `* [x]`, `1. [ ]`, 인용 안의 `> - [ ]` 까지 잡습니다
- **코드 블록 안의 `- [ ]` 는 건드리지 않습니다.** 네모로 그려지지 않으니 셈에서도 뺍니다
- 자리는 **몇 번째 네모인지**로 짚습니다. 그린 차례와 원문에 적힌 차례가 같기 때문입니다
- 네모가 든 줄에는 글머리 점을 찍지 않습니다. 표시가 둘이면 어수선합니다

### 이미지

`![설명](그림.png)` 과 `![[그림.png]]` 둘 다 됩니다. 볼트 안 파일을 찾는 순서는

1. 문서가 있는 폴더 기준 상대경로
2. 볼트 루트 기준 경로
3. 파일명이 같은 파일(여러 개면 경로가 짧은 쪽)

이라서 첨부를 한 폴더에 모아 두고 파일명만 적어도 됩니다.
찾지 못하면 그 자리에 안내가 표시됩니다.

이미지는 다른 첨부와 함께 **동기화 대상에 포함됩니다.** 아래 *첨부 파일* 을 보세요.

### 받는 형식을 보여 주는 자리

폴더를 고르면 나오는 "이 폴더에 파일 넣기" 칸은 받는 형식을 늘어놓습니다. 한 문단으로 이어
적었더니 **문서·압축·개발 소스가 한 덩어리로 흘러** 어디까지가 어느 갈래인지 알 수 없었습니다.

- 목록은 **놓는 자리(점선 칸) 밖으로 빼고 접어 둡니다.** 안에 펼쳐 두었더니 목록이 칸을 가득
  메워, 정작 파일을 놓을 자리가 눈에 들어오지 않았습니다. `첨부 가능 파일 목록` 단추를 눌러
  펴고 다시 눌러 접습니다 — 처음 쓸 때 한 번 궁금한 것이지 늘 펴 둘 것은 아닙니다.
  꺾쇠는 **다음에 누르면 일어날 일**을 가리킵니다: 접혀 있으면 아래(눌러서 펼침), 펴져 있으면
  위(눌러서 접음). `<select>` 와 여느 아코디언이 쓰는 결입니다. 지금 상태를 가리키게 하면
  (펴짐=아래) 눌렀을 때 어디로 갈지는 알 수 없습니다.
- 갈래는 **`attachments.ts` 한 군데에서 정하고**(`ATTACHMENT_GROUPS`) 화면은 그것을 그대로
  그립니다. 화면이 직접 묶었더니 압축을 더했을 때 그것이 `문서` 속으로 흘러들어 갔습니다.
- **마크다운은 첨부와 가릅니다**(`위키 문서` · `첨부`). 첨부가 아니라 위키의 본체라, 크기 제한
  없이 동기화되고 링크·검색·목차가 되는 것은 마크다운뿐입니다. 한 줄에 나란히 적어 두면
  "md 도 문서 아닌가" 싶고, 5MB 상한 같은 설명이 마크다운에도 걸리는 것처럼 읽힙니다.
  그래서 왜 따로인지를 그 자리에 한 줄로 적습니다.
- 갈래 이름은 **`개발 소스`** 입니다. `코드` 만으로는 무슨 코드인지 알 수 없습니다.
- 압축 갈래에는 **나눠 담은 조각도 받는다**는 것을 곁들입니다. 확장자만 늘어놓으면 `.001` 같은
  조각이 어디에도 없어 못 넣는 줄 압니다.

## 아주 큰 글 — 대용량 파일 모드

40MB 짜리 기록을 열었더니 열리기는 해도 **그 뒤가 쓸 수 없었습니다.** 화살표 한 번에 0.25초,
굴릴 때마다 0.26초. 재 보니 앱이 느린 것이 아니라 **글상자에 그만한 글을 담은 것 자체**가
그렇습니다 — 빈 쪽에 `<textarea>` 하나만 놓고 같은 글을 넣어도 같은 값이 나옵니다.
같은 글을 `<pre>` 에 담으면 굴리기가 0.23초에서 **0.04초**로 떨어집니다. 그래서 큰 글은
고치는 자리가 아니라 **보는 자리**로 엽니다.

- **자는 5MB 또는 4,000줄**입니다. 크기는 **파일 올리기 상한과 같은 값**을 씁니다 — 외울 숫자를
  둘로 늘리지 않습니다. 줄 수를 함께 보는 것은, 줄마다 요소가 서는 자리(줄 번호와 그 거울)가
  있어 **짧은 줄이 아주 많은 글은 크기가 작아도 요소 수로 먼저 무너지기** 때문입니다.
- 줄은 **자를 넘으면 거기서 그만 셉니다.** 대용량인지만 가리면 되므로 40MB 를 끝까지 셀
  까닭이 없습니다. 크기는 글자 수가 아니라 **파일에서 읽어 둔 바이트**로 봅니다 — 한글은
  한 자가 세 바이트라 글자 수로 세면 같은 파일에서도 자가 달라집니다.
- 그 글에서는 **고치기·미리보기·줄 번호·커서 위치가 모두 꺼집니다.** 넷을 따로 끄는 것이 아니라
  편집기 자체를 쓰지 않으므로 저절로 그렇게 됩니다.
- **글은 자르지 않습니다.** 보려고 연 사람에게 "뒤는 없습니다" 라고 할 수는 없습니다.
- 오른쪽 위에 **대용량 파일 모드** 딱지가 떠 있습니다. 평소에는 반쯤 비쳐(50%) 글을 가리지
  않고, 손을 얹거나 누르면 또렷해지며 **무엇이 꺼졌는지와 그 까닭**을 폅니다. 모르고
  "왜 안 고쳐지지" 하는 일이 없어야 합니다.
- 글자 파일에만 해당합니다. 그림·PDF·오피스는 가던 길 그대로입니다.

| 텍스트 첨부 (`txt` `csv` `tsv` `json` `yaml` `yml` `xml` `html` `htm`) | 이름과 본문 |
| 그림·PDF·오피스 문서 | 이름 |

- **이름이 걸린 쪽을 본문보다 훨씬 앞에 둡니다.** 보통은 이름으로 찾으니까요.
- 찾은 자리에는 **이름에도 발췌에도 같은 표시**가 붙습니다.
- 폴더가 걸리면 눌러서 그 폴더를 엽니다. 파일이면 그 파일이 열립니다.
- 결과 줄 앞 아이콘은 트리와 같은 색이라, 무엇이 걸렸는지 읽기 전에 보입니다.

**텍스트 첨부의 본문은 검색을 시작할 때 읽습니다.** 폴더를 열 때 미리 읽으면
표나 로그가 몇십 장만 있어도 여는 일이 눈에 띄게 느려집니다. 처음 한 번만 읽고
그 뒤로는 들고 있던 것을 씁니다. 읽는 동안에는 그렇다고 알려 주고, 다 읽으면
결과가 늘어납니다.

**큰 파일은 앞에서부터 1MB 까지만 읽어 둡니다.** 글자를 칠 때마다 훑어야 하는 자리라 수십
MB 를 통째로 들고 있을 수는 없는데, 그렇다고 빼 버리면 **이름으로만** 찾게 됩니다. 로그는
앞머리에 무엇이 든 파일인지 적혀 있는 일이 많아, 없는 것보다 앞부분이라도 찾히는 편이
낫습니다. 자른 파일에서 걸린 결과에는 발췌 끝에 **`· 앞부분에서`** 를 붙입니다 — 뒤에 더
있을지는 알 수 없으니 찾은 자리가 어디쯤인지는 밝혀야 합니다. 바이트로 자르면 글자 가운데가
쪼개지므로 **마지막 줄바꿈까지만** 남깁니다.

이 1MB 는 동기화 상한(5MB)보다 빡빡합니다. **올려 두기만 하는 값과 칠 때마다 훑는 값은
셈이 다릅니다** — 올리는 것은 한 번이고 검색은 글자 하나마다입니다.
**이름 검색은 크기와 상관없습니다.** 트리를 훑는 일이라 몇 GB 짜리라도 이름으로는 찾힙니다.

**찾기 전에 글자를 고르게 폅니다(NFC).** 맥은 파일 이름을 **자모가 분리된 꼴(NFD)** 로 적어
두는데 치는 글자는 모아진 꼴이라, 눈에는 똑같은 글자가 바이트로는 달라 **"분명히 있는데 안
찾히는"** 일이 생깁니다(앱이 만든 파일은 적은 대로 모아진 꼴이라, 밖에서 들어온 파일에서만
드러납니다). 이름 찾기와 즐겨찾기 거르기가 **같은 잣대**를 씁니다.

**즐겨찾기 탭**의 찾는 칸은 담아 둔 것을 **이름으로만** 거릅니다.
몇십 개 안 되는 목록에서 하나를 집어내는 일이라 본문까지 뒤질 까닭이 없습니다.

## 첨부 파일

마크다운이 아닌 파일도 다룹니다. 다만 **아무 파일이나 받지는 않습니다** —
git 은 한 번 올린 바이너리를 이력에 영구히 남겨서, 지워도 저장소가 줄지 않기 때문입니다.
아래가 넣을 수 있는 형식의 전부입니다. 마크다운은 이 위키의 본래 형식이라 늘 받습니다.

| 갈래 | 확장자 |
| --- | --- |
| 마크다운 | `md` |
| 이미지 | `png` `jpg` `jpeg` `gif` `webp` `svg` `avif` `bmp` `ico` |
| 문서 | `pdf` `txt` `csv` `tsv` `json` `yaml` `yml` `xml` `html` `htm` `doc` `docx` `xls` `xlsx` `ppt` `pptx` `hwp` `hwpx` |
| 코드 | `sql` `js` `mjs` `cjs` `jsx` `ts` `tsx` `py` `sh` `bash` `zsh` `java` `kt` `kts` `go` `rs` `c` `h` `cpp` `cc` `hpp` `cs` `swift` `rb` `php` `lua` `pl` `r` `css` `scss` `less` `ini` `toml` `properties` `diff` `patch` `graphql` `gql` `makefile` |

- **5 MB 를 넘는 첨부는 동기화하지 않습니다.** 목록에는 보이고 미리보기도 되지만,
  이 컴퓨터에만 남습니다. 마크다운에는 이 제한이 없습니다.
- 목록에 없는 형식은 트리에 나타나지 않고 동기화도 하지 않습니다.
- 이름 바꾸기와 폴더 옮기기는 **바이트를 그대로** 옮깁니다.
  텍스트로 한 번이라도 거치면 이미지 같은 파일이 되돌릴 수 없게 망가집니다.
- 이름을 바꿀 때 확장자를 적지 않으면 원래 확장자를 그대로 붙입니다.
### 첨부를 고르면

| 형식 | 편집 | 미리보기 |
| --- | --- | --- |
| `csv` `tsv` | 가능 | **표**로 그립니다 |
| `json` `yaml` `yml` `xml` | 가능 | 색을 입혀 보여 줍니다 |
| 코드 (`sql` `py` `js` `ts` … 위 표) | 가능 | **실행하지 않고 문법 강조만** 해서 보여 줍니다. 강조기(highlight.js common)가 아는 말만 받으며, `jsx`·`tsx` 는 javascript·typescript 로, `toml`·`properties` 는 `ini` 로 읽습니다 |
| `html` `htm` | 가능 | **그리지 않고 문법 강조**로 보여 줍니다 |
| `txt` | 가능 | 그릴 것이 없어 편집기만 씁니다 |
| `xlsx` `xls` | — | **표**로 그립니다. 시트가 여럿이면 탭으로 오갑니다 |
| `docx` | — | 제목·목록·표·굵기와 그림까지 **글로 풀어** 보여 줍니다 |
| `doc` `ppt` | — | 열지 못합니다. 어느 형식으로 저장하면 되는지 알려 줍니다 |
| `png` `jpg` `jpeg` `gif` `webp` `svg` `avif` `bmp` `ico` | — | 그림으로 봅니다. 제목 줄에서 뒤에 깔 바탕을 고를 수 있고, 설정에서 아예 끌 수도 있습니다 |
| `pdf` | — | 브라우저 PDF 보기로 봅니다 |
| `docx` `xlsx` `pptx` `hwp` `hwpx` | — | 지원하지 않습니다. 파일은 폴더에 그대로 있습니다 |

편집할 수 있는 형식은 마크다운과 똑같이 자동 저장되고, 미리보기가 있는 형식은
**편집 / 나란히 / 미리보기** 를 오갈 수 있습니다.

### 그림 수정

그림을 고르면 제목 줄에 **수정** 단추(연필)가 섭니다. `⌘⇧E` 로도 여닫습니다 — 문서에서 보기
모드를 돌리는 글쇠와 같은 것입니다. 둘 다 "지금 보고 있는 것을 다르게 보는" 일이라 하나로 둡니다.
형식 바꾸기(PNG·JPG) · 크기 줄이기 · 잘라내기(비율 씌우기까지) · 돌리기와 뒤집기만 둡니다. 그림판을 만들려는
것이 아니라, 문서에 넣기 전에 흔히 한 번 거치는 손질을 앱 밖으로 나가지 않고 끝내려는 것입니다.

- 수정 화면은 **본문에 남은 키를 다 씁니다.** 내용만큼만 서 있었더니 아래가 잘린 것처럼
  보였고, 저장·취소가 그림 한가운데쯤에 떠 있었습니다. 그 둘은 손잡이 칸 **맨 아래**에 붙고,
  칸이 길어져 굴러가도 바닥에 따라옵니다.
- **덮개 창이 아니라 본문 자리에서 엽니다.** 고치는 동안에도 옆줄과 제목 줄이 그대로 보여야
  어느 파일을 만지고 있는지 알 수 있고, 창이 작을 때 고칠 자리가 덮개에 갇히지 않습니다.
  그동안 제목 옆의 `읽기 전용` 은 **`수정 모드`** 로 바뀝니다.
- **이름은 `사진_modified.png` 처럼 먼저 지어 두되 고칠 수 있습니다.** 꼬리말에 빈칸과 괄호를
  쓰지 않는 것은, 웹에 올리거나 명령줄에서 다룰 때 따옴표로 감싸야 하고 주소에서는 `%20` 으로
  바뀌어 읽기 어렵기 때문입니다. 같은 이름이 이미 있으면
  **덮어쓸지 먼저 묻고**, 되돌릴 수 없다는 것과 문서에 끼워 넣은 자리도 함께 바뀐다는 것을
  밝힙니다. 물러서면 아무것도 쓰지 않고 수정 화면에 머뭅니다 — 다른 이름으로 바꿔 저장하면 됩니다.
  만든(또는 덮어쓴) 뒤에는 그 파일을 곧바로 엽니다. 무엇이 나왔는지 눈으로 봐야 다시 고칠지
  정할 수 있습니다. 덮어쓴 그림은 캐시에서도 지웁니다 — 잊지 않으면 문서 안에 옛 그림이 남습니다.
- 손잡이 칸의 단추·고르개·입력란은 **작은 단추 하나(28px)를 자로 삼아** 키를 맞춥니다.
  저마다 다른 키를 지니고 있어 줄마다 높이가 들쑥날쑥했고, 같은 줄에 섞여 서면 가운데가
  맞지 않았습니다. 큰 쪽이 아니라 **가장 작은 것**에 맞추는 것은, 좁은 칸에서 손잡이만으로
  한 화면이 차 버리기 때문입니다. 저장·취소는 그대로 둡니다 — 칸이 아니라 마무리 자리입니다.
  비율 딱지는 **너비까지 같게**(격자) 둡니다. 글자 수대로 재면 `1:1` 과 `16:9` 의 너비가 달라
  줄이 바뀔 때마다 왼쪽 끝이 어긋나, 여덟이 한 묶음으로 읽히지 않았습니다.
- 손잡이 칸의 **잘라내기**는 줄마다 왼쪽에 이름을 세웁니다(`비율 고정` · `긴 쪽` · `고른 자리`).
  딱지만 늘어놓았더니 `4:3` 이 무엇을 하는 단추인지, `가로` 가 어디에 걸리는 말인지 눌러
  보기 전에는 알 수 없었습니다. 이름의 오른쪽 끝을 맞춰 두면 단추들의 왼쪽 끝도 한 줄로 섭니다.
- **보기 배율**은 **보기 모드와 수정 화면이 같은 손잡이**를 씁니다. 작은 그림에서 몇 픽셀을
  집어내려면 키워 놓아야 하고, 큰 그림은 줄여 놓아야 한눈에 듭니다. 보기에서는 제목 줄이 아니라
  **그림 위에 떠 있습니다**(문서의 맨 위·맨 아래 단추와 같은 자리). 제목 줄에 두었더니 그림을
  보던 눈이 멀리 갔고, 좁은 화면에서는 제목 줄이 두 줄로 접혔습니다. 세로로 **화면 맞춤 ·
  원본 크기 · 확대 · 배율 · 축소**, 가운데는 눌러서 배율을 적어 넣는 자리입니다.
  다만 **굴러가는 칸(`.asset-canvas`·`.image-edit-stage`) 안에 두지는 않습니다.** 안에 두었더니
  크게 키워 놓고 그림을 옮길 때 손잡이가 내용과 함께 밀려 나가, 누르려면 그림을 쫓아가야
  했습니다. 굴러가지 않는 바깥 칸에 붙이고 그 칸을 자리 기준으로 삼습니다(크기 딱지도 같은
  까닭으로 함께 옮겼습니다).
  **고칠 때도 같은 자리에 같은 낯(반투명·흐림)으로 뜹니다.** 고칠 때만 손잡이 칸 안에 누워
  있었더니, 같은 일을 하는 손잡이를 두 군데서 다르게 찾아야 했습니다. 화면 맞춤이 값으로
  남는 것만 다릅니다 — 잘라 낼 자리를 재려면 배율이 늘 또렷한 값이어야 합니다.
- 눈금은 **큰 쪽일수록 성글게** 벌립니다 — 100% 아래는 20% 씩, 100~200% 는 25% 씩,
  200~300% 는 50% 씩. 같은 20% 라도 40 → 60 은 한눈에 달라 보이지만 250 → 270 은 거의 같아
  보이기 때문입니다. 맨 아래 **10%** 는 따로 두고(아주 큰 그림은 20% 로도 한 화면에 들지
  않습니다), 맨 위는 **300%** 입니다.
- **배율을 눌러 손으로 적어 넣을 수도 있습니다**(`Z`). 10 ~ 300 사이, 그 밖의 값은 가까운
  끝으로 맞춥니다. 단계로는 닿지 않는 값(110% 같은)을 쓰거나 여러 그림을 같은 배율로 견줄 때
  씁니다. 창을 띄우는 길은 손잡이와 단축키가 한 자리를 쓰므로 묻는 말과 값의 끝이 어긋나지 않습니다.
- **확대·축소는 지금 그려진 배율에서 한 걸음** 옮깁니다. 표에 없는 값에서도 세어야 합니다 —
  화면 맞춤은 칸에 따라 37% 처럼 어중간한 값이 되는데, 표에서 자리를 못 찾아 100% 부터 세었더니
  키우려고 눌렀는데 150% 로 건너뛰었습니다.
- 숫자를 받는 물음 창(행·열, 배율)에서 **단위는 칸 뒤에** 섭니다. 위에 얹었더니 숫자와 떨어져
  어디에 걸리는 말인지 흐렸습니다. 이름이 없는 칸(배율처럼 창 이름만으로 충분한 때)은 이름 줄을
  아예 비웁니다.
- 아이콘을 품은 단추는 글자와 가운데를 맞춥니다(`.btn:has(.icon)`). 그냥 두면 그림이 글자의
  밑줄에 앉아 한 픽셀씩 내려가 보입니다.
- 배율을 정해 두었어도 **칸보다 작으면 가운데**에, 커지면 **왼쪽 위부터** 보입니다(`safe center`).
  그냥 가운데로 모으면 큰 그림의 위와 왼쪽이 칸 밖으로 밀려 굴려도 닿지 않습니다.
- 보기 모드는 `맞춤`(칸에 맞춰 줄이기)에서 시작하고, 파일을 바꾸면 맞춤으로 되돌립니다 —
  앞 그림의 배율이 다음 그림에 맞을 까닭이 없습니다.
- 그림을 볼 때는 **맨 글쇠**로도 다룹니다: `+`(또는 `=`) 확대 · `-` 축소 · `0` 화면 맞춤 ·
  `1` 원본 크기 · `Z` 배율 적어 넣기. 글을 치는 자리(검색 칸·편집기)에서는 가로채지 않습니다.
  **고치는 중에도 같은 글쇠가 듣습니다** — 같은 그림을 같은 자리에서 보고 있는데 글쇠만 달라질
  까닭이 없습니다(그때는 수정 화면이 스스로 받습니다). 거기에 더해 `⌘S` 로 저장하고 `Esc` 로
  그만둡니다. `Esc` 는 겹쳐 뜬 창의 차례를 따르므로 물음 창이 떠 있으면 그쪽이 먼저 닫힙니다.
- 미리보기 오른쪽 위에는 **형식(PNG·JPG·SVG …)** 과 크기가 함께 적힙니다.
- **떠 있는 단추(배율 손잡이·목차 단추)는 바탕만 비칩니다.** 아래에 무엇이 있는지 보이되 글자는
  그대로여야 하므로, 통째로 흐리지(`opacity`) 않고 **바탕색만** 82% 로 두고 뒤를 흐립니다
  (`backdrop-filter: blur(12px)`). 처음에는 82% 로 두었는데 비치는지 알아보기 어려워 66% 까지
  내렸습니다. 대신 글씨는 흐린 색을 걷고 본문 색으로 또렷하게 둡니다 — 바탕이 비치는 만큼
  글씨가 묻히면 안 됩니다. 켜 둔 단추는 덜 비치게(90%) 두어 켜진 것이 분명히 보이게 합니다.
  가장자리와의 틈은 문서의 맨 위·맨 아래 단추와 같은 24px 입니다.
- **수정 화면에도 화면 맞춤이 있습니다.** 지금 배율이 맞춤 값과 같으면 단추가 켜집니다
  (원본 크기 단추처럼). 맞춤 배율을 잴 때 칸의 크기는 **굴림대를 뺀 안쪽이 아니라 테두리까지**
  잽니다 — 안쪽으로 재면 굴림대가 섰느냐에 따라 값이 달라져, 거듭 누를 때마다 46% 와 47%
  사이를 오갔습니다(굴림대가 자리를 먹는 설정에서). 맞추고 나면 넘치지 않아 굴림대가 없으므로
  굴림대가 없는 셈으로 재는 것이 맞습니다. 창 크기가 바뀌면 맞춤 값을 다시 재되, 보고 있는
  배율은 건드리지 않습니다. 크게 키워 보다가 다시 한눈에 담고 싶은 일이 잦습니다.
  보기 모드와 달리 그 값이 그대로 남으므로, 잘라 낼 자리를 재는 데에도 걸림이 없습니다.
- **수정 화면은 칸에 꽉 차는 배율로 엽니다.** 100% 로 열었더니 큰 그림은 한 귀퉁이만 보여
  어디를 고르는지 알 수 없었고, 작은 그림은 너른 칸 한가운데 조그맣게 놓여 픽셀을 집어내기
  어려웠습니다. 배율은 1% 눈금으로 **내림**합니다 — 반올림하면 한 픽셀 넘쳐 굴림대가 생기는데,
  꽉 채우려다 굴림대를 부르는 것은 얻는 것보다 잃는 것이 큽니다. 한 번만 잡고, 그 뒤로는
  사람이 고른 배율을 덮지 않습니다.
- 수정 화면의 그림 칸은 **폭을 묶지 않습니다.** 칸 너비에 묶어 두었더니 거기서 더 키워지지
  않아, 크게 보며 고를 수가 없었고 보이는 데까지만 골라졌습니다. 넘치면 칸이 가로로 굴러갑니다.
- **내놓을 크기는 원본 대비 몇 할로도 고릅니다**(원래 크기 · 200% · 150% · 50% · 25%).
  반으로 줄이는 일이 잦은데 그때마다 두 칸에 손으로 적어야 했습니다. 몇 할인지는 **지금 적힌
  수가 아니라 원본(고른 자리) 대비**입니다 — 적힌 수의 몇 할로 두면 두 번 누를 때마다 값이
  겹쳐 줄어, 50% 를 두 번 누른 사람이 25% 를 기대하기 어렵습니다. 원래 크기가 곧 100% 자리입니다.
  키우는 쪽을 둘만 둔 것은 없는 점을 지어내는 일이라 많이 키울수록 뭉개지기 때문입니다.
  너비·높이 칸은 **여섯 글자**면 넉넉합니다(가장 큰 값이 10000) — 92px 로 두었더니 칸이 값보다
  훨씬 넓어, 옆에 설 자리가 모자라면서도 안은 비어 보였습니다.
- **비율을 씌워 고를 수 있습니다**: 자유 · 1:1 · 4:3 · 16:9 · 3:2 · 5:3 · 5:4 · 7:5, 그리고
  **긴 쪽**을 가로로 눕힐지 세로로 세울지. 인화지나 화면에 맞춰 넣을 그림은 비가 정해져
  있는데, 눈으로 맞춰 끌면 늘 한두 픽셀이 어긋나고 그 어긋남은 넣어 보기 전에는 보이지
  않습니다. 임의의 비를 적어 넣는 길은 두지 않습니다 — 여기서 하는 일은 "어디에 넣을
  그림인지" 를 고르는 것이지 비를 만들어 내는 것이 아닙니다.
- 딱지의 글은 **고르면 나올 그대로** 적습니다(세우면 `16:9` 가 `9:16`). 이름만 그대로 두고
  속으로만 뒤집으면 눌러 보기 전에는 어느 쪽이 길어지는지 알 수 없습니다.
- 비율을 씌운 채 끌면 **손끝을 덮는 쪽**(두 축 가운데 큰 쪽)에 맞춥니다. 작은 쪽에 맞췄더니
  손은 저만치 갔는데 네모가 따라오지 않아 끌리지 않는 것처럼 보였습니다. 변을 잡아 한 축만
  움직일 때는 다른 축이 **가운데를 지키며** 따라옵니다 — 한쪽 끝을 붙박이로 두면 옆으로
  늘일 때마다 네모가 위아래로 미끄러집니다. 그림 밖으로 넘치면 **비율을 지킨 채 줄입니다**.
  안으로 밀어 넣기만 하면(`clampCrop`) 붙박이로 둔 꼭지점이 손에서 빠져나갑니다.
- **비율을 갈아 끼우면 이미 고른 자리도 그 비로 다시 잡습니다.** 그대로 두면 "16:9 를
  골랐는데 화면의 네모는 아무 비" 인 채로 남아 다시 끌어야 비로소 먹습니다. 고른 네모
  **안에** 들어가도록 줄이므로(넓이를 지키며 늘이지 않습니다) 그림 밖으로 나갈 일이 없습니다.
- **고른 칸 안쪽을 잡으면 그 자리를 통째로 옮깁니다**(마우스가 `move` 로 바뀝니다). 크기는 맞는데
  자리만 조금 어긋나는 일이 잦은데, 그때마다 다시 고르게 하면 크기를 또 맞춰야 합니다.
  그림 밖으로는 나가지 않습니다.
- **바깥을 그냥 누르면(끌지 않고) 고른 자리가 풀립니다.** 바깥에서 끌면 예전처럼 새로 고릅니다 —
  누른 뒤 손이 움직였는지로 둘을 가립니다. 안쪽은 옮기는 자리, 테두리는 늘이는 자리, 바깥은
  새로 고르거나 그만두는 자리입니다.
- **고른 자리는 다시 고칠 수 있습니다.** 네 변과 네 꼭지점에 손잡이가 서서, 변을 잡으면 그 축만
  (가로 또는 세로), 꼭지점을 잡으면 두 축이 함께 움직입니다. 한 번에 딱 맞게 끄는 일은 드물고,
  조금 넓거나 좁게 고른 것을 다시 그리게 하는 것은 성가십니다. 잡은 손잡이의 **맞은편**을
  붙박이로 두면 새로 고르는 것과 똑같은 셈으로 늘이기까지 다룰 수 있습니다.
  다 고친 뒤 **선택 영역 해제**를 누르면 고른 자리가 지워지고 그림 전체로 돌아갑니다.
  변은 보이지 않는 띠로 두고 꼭지점만 네모를 세웁니다 — 변마다 네모를 세우면 작게 고른
  자리에서 네모끼리 겹쳐 무엇을 잡는지 알 수 없습니다. 띠는 테두리 바깥으로 조금 걸쳐
  둡니다(한 픽셀 선을 정확히 짚기는 어렵습니다).
- **왼쪽 단추로만 고릅니다.** `pointerdown` 은 어느 단추든 똑같이 오므로, 가리지 않았더니
  오른쪽 단추로 눌러도 고르기가 시작되어 메뉴를 부르려던 손이 고른 자리를 통째로 지웠습니다.
  오른쪽 단추는 브라우저에 그대로 넘깁니다 — 그림 저장하기 같은 제 할 일이 있습니다.
- **손가락 옆에 쪽지가 따라다닙니다.** 누르기 전에는 그림에서 짚고 있는 자리(`180, 20`),
  고르는 중에는 고른 크기(`101 × 81`). 잘라내기는 픽셀 단위로 맞추는 일인데, 아래 칸의 숫자를
  보려면 눈이 손에서 멀리 떠나야 했습니다. 쪽지는 손 밑에 깔리지 않게 오른쪽 아래로 비끼고,
  화면 끝에서는 안쪽으로 접습니다. 누르는 것을 막지 않습니다(`pointer-events: none`).
- **스페이스를 누르고 있으면 끌어서 그림을 옮깁니다**(손 모양으로 바뀝니다). **보기 모드와 수정
  화면이 같은 손잡이**(`useSpacePan`)를 씁니다 — 크게 키워 놓으면 어느 쪽에서든 굴림대까지 손을
  옮겨야 하고, 수정 화면에서는 끌기가 곧 고르기라 아예 쓸 수 없습니다.
  **켜 둔 동안에는 스페이스를 늘 가로채고 기본 동작도 막습니다.** 브라우저는 스페이스를
  "한 화면 내리기"로 쓰는데, 손이 어디 있는지 따져 가며 가로챘더니 그 밖에서는 화면이 덜컥
  내려갔습니다. 그 대신 그동안에는 스페이스로 단추를 누를 수 없습니다 — 자판만 쓰는 사람은
  `Enter` 로 누르면 됩니다. 글을 치는 자리에서는 그대로 빈칸입니다.
  **옮길 것이 없으면 켜지 않습니다**(보기 모드의 화면 맞춤처럼 칸에 다 들어오는 때). 가로챌
  까닭이 없습니다. 옮기는 동안에는 손잡이도 옮기는 자리가 되고, 고른 자리는 건드리지 않습니다.
- **칸 가장자리까지 끌고 가면 저절로 굴러갑니다.** 잡은 손으로는 굴림대를 만질 수 없고 놓으면
  거기서 끝나므로, 끄는 동안 칸을 대신 굴려 줍니다. 손가락을 멈춰 두어도 이어지도록 프레임마다
  다시 보고, 칸이 움직인 만큼 고른 자리도 다시 셉니다.
- **돌리기와 뒤집기**: 왼쪽·오른쪽으로 90°, 좌우 뒤집기, 상하 뒤집기. 폰으로 찍은 그림이 옆으로
  누워 있거나 거울에 비친 듯 뒤집혀 오는 일이 흔한데, 그것 하나 고치자고 다른 프로그램을 여는
  것은 과합니다. **90° 단위만** 둡니다 — 그 사이 각으로 돌리면 네 귀퉁이에 빈 자리가 생겨
  무슨 색으로 채울지부터 정해야 하고, 그것은 이 화면이 하려는 손질이 아닙니다.
- **셈은 모두 "보이는 대로"** 합니다. 잘라낼 자리도, 내놓을 크기도, 덮개도 돌린 뒤의 좌표입니다.
  본디 좌표로 셈했더니 90° 돌려 놓은 그림에서 손가락이 짚은 자리와 덮개가 어긋났습니다.
  그려 낼 때도 **돌리고 뒤집은 판을 한 장 먼저 만들고** 그 위에서 자릅니다. 한 번에 그리려면
  화면에서 고른 자리를 본디 좌표로 되짚어야 하는데, 네 방향 × 네 가지 뒤집기 가운데 한 조합은
  늘 어긋났습니다. 판 한 장이 셈을 한 갈래로 줄이는 값입니다.
- **뒤집기는 돌린 뒤의 축이 아니라 화면의 가로·세로**입니다. 90° 돌려 놓고 좌우 뒤집기를 눌렀는데
  위아래가 뒤집히면 무엇을 누른 것인지 알 수 없습니다. 그래서 화면에 그리는 CSS 변환과 canvas
  그리기가 **같은 차례**(뒤집기를 돌리기보다 앞에)를 쓰도록 한 군데(`orientCss`)에서 짓습니다.
  두 곳에서 따로 적으면 화면과 나온 파일이 달라집니다.
- **돌리거나 뒤집으면 고른 자리는 풉니다.** 돌리면 가로세로가 바뀌어 그 자리가 뜻을 잃고,
  뒤집기는 크기가 그대로여도 덮개 안의 그림이 딴 것이 됩니다. 어떤 단추를 눌렀느냐에 따라
  남기도 하고 풀리기도 하면 짐작할 수 없어 한 가지로 둡니다. 내놓을 크기도 새 크기로 되돌립니다.
  **맞춤으로 보고 있었으면 돌린 뒤에도 다시 맞춥니다** — 가로로 길던 그림이 세로로 서면 칸을
  넘쳐 아래가 잘린 채 남습니다. 배율을 손으로 정해 둔 사람의 값은 건드리지 않습니다.
- 칸은 **설명 → 단추 → 바뀐 내용** 차례입니다. 지금 방향(`오른쪽으로 90° · 좌우 뒤집음`)은
  단추 **아래 줄**에 적습니다 — 단추 옆에 붙여 두었더니 마지막 단추의 이름처럼 읽혔습니다.
  손댔을 때만 **되돌리기**가 서고(몇 번 눌렀는지 세어 가며 거꾸로 돌리게 할 까닭이 없습니다),
  뒤집기는 눌린 채로 남으므로(같은 단추를 다시 눌러 풉니다) 켜진 것을 색으로 알립니다.
- 돌리기 아이콘은 화살 **머리를 획의 끝**에 붙이고 몸통을 지나온 쪽으로 뻗습니다. 머리를 획의
  시작에 붙였더니(12시에서 오른쪽을 가리키는데 획은 3시·6시·9시로 뻗음) 눈에는 "9시에서
  올라온 반시계" 로 읽혀 왼쪽·오른쪽 단추가 서로 바뀐 것처럼 보였습니다. 뒤집기 아이콘은
  접는 금을 사이에 둔 두 쐐기이고 **한쪽만 칠합니다** — 둘 다 테두리로만 그렸더니 16픽셀에서
  두 쐐기가 붙어 마름모 하나로 보였습니다.
- 그림 틀의 테두리는 `border` 가 아니라 `outline` 입니다. border 는 두께만큼 안쪽을 줄이는데
  그림은 칸 크기 그대로 그려지므로 2픽셀이 어긋나, 고른 덮개가 그림보다 살짝 밀려 그려집니다.
  그림 자체도 흐름에 두지 않고 칸 가운데에 붙여 놓고 돌립니다 — 흐름에 두면 돌아간 그림이
  돌기 전의 자리를 그대로 차지해, 세로로 선 그림 옆에 가로만큼의 빈 자리가 남습니다.
- **잘라낼 자리는 그림 위를 끌어** 고릅니다. 화면에 그려진 크기는 배율만큼 줄거나 늘어
  있으므로, 잰 값을 **보이는 대로의 크기**(돌린 뒤의 크기)로 되돌려 적어 둡니다. 재는 것은 칸이 아니라 **그림**입니다 — 칸은 테두리
  만큼 크고, 그림이 칸보다 작을 수도 있습니다. 가장자리를 넘어가게 끌면 그림 안으로 밀어
  넣습니다. 그대로 그리면 빈 자리가 검게 남습니다.
- 잘라 낸 뒤에는 내놓을 크기도 그 크기로 되돌립니다. 앞서 적어 둔 수는 뜻이 달라집니다.
- **가로세로 비율 지키기**를 켜 두면 한쪽만 적어도 다른 쪽이 따라옵니다(기본 켜짐).
- **JPG 에는 투명이 없습니다.** 그냥 그리면 투명한 자리가 검게 나오므로 흰 바탕을 먼저 깝니다 —
  검정보다 흰 쪽이 원래 모습에 가깝습니다. 품질은 10 ~ 100% 로 정합니다(기본 90%). PNG 는
  버리는 것이 없어 그 값이 뜻이 없으므로 아예 내놓지 않습니다.
- 그리는 일은 브라우저의 canvas 로 합니다. 서버가 없으니 파일이 밖으로 나가지 않습니다.

### 압축 파일 — 풀지 않고 목록만

`.zip` 을 첨부로 받고, 고르면 **안에 무엇이 들었는지 목록**을 보여 줍니다.

- **풀지 않습니다.** zip 은 파일 끝에 목차(중앙 디렉터리)를 두므로 **끝의 몇 킬로바이트만**
  읽으면 이름·크기·적어 둔 때를 알 수 있습니다. 100MB 짜리라도 읽는 양은 같습니다.
  내용을 꺼내려면 풀어야 하고 그러려면 deflate 를 들여야 하는데, 여기서 하려는 일은
  "이 압축이 무엇이었더라" 를 가리는 것이지 파일을 꺼내 쓰는 것이 아닙니다.
- **받는 것과 읽는 것을 가릅니다.** `zip` `rar` `7z` `alz` 와 **나눠 담은 조각**(`.001` `.r01`
  `.z01` `.a01`)을 모두 첨부로 받아 보관하고 동기화하지만, **안엣것 목록을 읽는 것은 zip 뿐**입니다.
  7z 은 목차 자체가 LZMA 로 눌려 있어 푸는 코드를 들이지 않고는 이름 하나 꺼낼 수 없고,
  rar·alz 는 규격이 공개돼 있지 않습니다. 못 읽는 것은 **왜 못 읽는지 적고** 파일은 그대로
  둡니다 — 못 읽는다고 넣지도 못하게 할 까닭은 없습니다.
- **나눠 담은 zip 조각은 이어서 읽습니다.** 조각 하나만 읽으면 목차가 마지막 조각에만 있어 늘
  실패합니다. 같은 바탕 이름의 조각을 차례대로 모아 하나처럼 봅니다. 어느 조각을 골라도 같은
  목록이 나옵니다. `new Blob([...])` 은 바이트를 모아 두지 않고 **가리키기만** 하므로,
  4GB 를 나눠 담았어도 메모리로 들어오는 것은 목차 몇 킬로바이트뿐입니다.
- 목록에서 압축은 **문서와 다른 아이콘**(뚜껑·몸통·잠금쇠)을 씁니다. 같은 모양이면 가릴 수 없습니다.
- 파일 고르기 창의 거름 목록에는 **흔한 조각 번호만**(001~009, r00~r09 …) 적습니다. 조각 번호는
  999까지 있어 다 적을 수 없습니다 — 그 밖의 조각은 끌어다 놓거나 폴더에 그대로 두면 들어옵니다.
- **이름의 글자 꼴은 읽어 보고 가립니다.** 규격은 "깃발(bit 11)이 섰으면 UTF-8, 아니면 CP437"
  이라고만 말하지만 실제와 다릅니다 — **맥의 압축은 깃발 없이 UTF-8 로** 적고, 윈도 압축기는
  저마다 제 나라 글자 꼴(우리나라는 CP949)로 적습니다. 깃발만 믿었더니 맥에서 만든 압축의
  한글 이름이 통째로 깨졌습니다(UTF-8 바이트를 EUC-KR 로 읽은 꼴).
  - **적어 둔 것이 있으면 그것을 씁니다.** 제 나라 글자 꼴로 적으면서 원래 이름을 UTF-8 로
    한 번 더 적어 두는 압축기가 있습니다(Info-ZIP Unicode Path, 0x7075). 가장 미덥습니다.
  - 그 밖에는 **읽어 보고 점수를 매겨** 고릅니다. 후보는 `utf-8` `euc-kr` `shift_jis` `gbk` `big5`.
    읽다 막히는 꼴(`fatal`)은 그 자리에서 떨어뜨리고, 옮긴 글에 **한글·가나·한자가 고르게**
    나오면 높이고 쓰이지 않는 기호나 제어 문자가 섞이면 깎습니다. 잘못 읽으면 그 기호가
    쏟아지므로 그것으로 옳은 꼴이 갈립니다. 한국어뿐 아니라 일본어·중국어 압축도 함께 풀립니다.
  - **압축 하나에는 한 꼴**로 적혀 있으므로 이름을 모두 모아 **한 번만** 정합니다. 이름마다
    따로 정하면 같은 압축 안에서 어떤 이름은 한글로, 어떤 이름은 한자로 읽히는 일이 생깁니다.
    이미 UTF-8 이라고 밝힌 이름은 가리는 데 섞지 않습니다 — 그쪽으로 쏠려 가려낼 수 없습니다.
- **폴더 안엣것은 들여씁니다.** 긴 경로를 통째로 적어 두었더니(`자료/안쪽/메모.txt`) 어느 것이
  어느 폴더 아래인지 눈으로 좇기 어려웠습니다. 깊이만큼 밀고 **마지막 마디만** 적되, 온 경로는
  쪽지로 남깁니다 — **폴더 자리가 아예 없는 압축**(폴더를 적지 않는 압축기가 있습니다)에서
  경로를 잃으면 안 되기 때문입니다.
- **폴더 이름은 또렷하고 굵게.** 처음에는 "크기가 없는 줄" 이라 흐리게 두었는데, 되레 읽기
  어려웠습니다. 안엣것을 가르는 머리글이라 어디서부터 그 폴더인지 한눈에 들어와야 합니다.
- 보이는 것은 `unzip -l` 과 같은 결입니다 — **이름 · 크기 · 압축 크기 · 압축율 · 최종 수정일시**,
  그리고 합계(`총 3개 파일 · 3 MB`)는 목록 **아래** 한 줄. 위에 두면 목록을 보기 전에 숫자부터
  읽게 됩니다. "풀지 않습니다" 같은 군말은 두지 않습니다 — 목록만 나오는 화면이 그것을 말합니다.
- **생성일시는 있는 압축에만** 칸이 섭니다. zip 의 기본 기록에는 지은 때가 없고, 윈도가 덧붙이는
  NTFS 칸(0x000a)에만 100나노초 단위로 들어 있습니다. 유닉스 쪽은 0x5455 칸에 초 단위로
  고친 때를 적습니다. 덧붙은 칸이 있으면 그쪽이 더 촘촘하므로 그것을 쓰고(MS-DOS 꼴은 2초
  단위라 홀수 초가 깎입니다), 없으면 빈 칸을 세우지 않습니다 — 없는 때를 지어내지 않습니다.
- 항목이 아주 많으면 **앞 2,000개만** 그리고 전체가 몇 개인지 적습니다.
- **4GB 를 넘거나 항목이 65,535개를 넘는 압축(zip64)** 은 끝자락에 자리 지킴이만 남아 읽을 수
  없습니다. 틀린 목록을 보여 주느니 **못 읽는다고 밝힙니다.** 목차를 못 찾는 파일(조각나거나
  zip 이 아닌 것)도 같습니다.
- `docx`·`xlsx`·`pptx` 도 속은 zip 이지만 그쪽은 글과 표로 풀어 보여 줍니다. 여기까지 내려온
  `.zip` 만 목록으로 봅니다.
- 오피스 미리보기 설정과는 따로 둡니다. 읽는 양이 몇 킬로바이트뿐이라 끌 까닭이 없습니다.

### 오피스 파일

**엑셀과 워드는 앱 안에서 바로 봅니다.** 서버 없는 앱이라 브라우저에서 직접 풉니다.

- **엑셀**(`xlsx` `xls`)은 CSV 와 같은 표 화면에 그립니다. 셀은 서식이 입혀진 글자
  그대로 가져오므로 날짜가 `45000` 같은 일련번호로 나오지 않습니다.
  시트가 여럿이면 표 위 탭으로 오갑니다. 500행까지만 그리고 나머지는 셈만 알려 줍니다.
- **워드**(`docx`)는 글로 풀어 보여 줍니다. 쪽 나눔이나 여백까지 그대로 옮기지는
  못하고, 읽는 데 필요한 것(제목·목록·표·굵기·그림)만 살립니다.
  파일에서 온 HTML 이므로 **그리기 전에 걸러 냅니다.**
- **읽는 벌은 그 파일을 열 때만 내려받습니다.** 다이어그램·수식과 같은 방식이라
  첫 화면 무게는 그대로입니다.
- `doc` `ppt` 같은 **옛 이진 형식은 브라우저에서 풀 방법이 사실상 없습니다.**
  못 연다고만 하면 무엇을 해야 할지 알 수 없으니, `docx`·`pptx` 로 저장하면 된다고
  일러 줍니다. `pptx` 와 한글 파일은 아직 미리보기가 없습니다.

표는 따옴표로 감싼 칸과 그 안의 쉼표·줄바꿈을 규격대로 읽습니다.
행이 아주 많으면 앞 500행만 그립니다.

**JSON 은 들여쓰기를 자동으로 맞춥니다.**

- 미리보기는 원문이 어긋나 있어도 늘 정돈해서 보여 줍니다. 파일은 건드리지 않습니다.
- 파일 자체는 **그 파일에서 벗어날 때** 정돈해 저장합니다.
  글을 쓰는 도중에 바꾸면 커서가 엉뚱한 곳으로 튀기 때문입니다.
- 정돈은 `JSON.parse` 를 거치지 않고 공백만 다시 넣습니다.
  거치면 큰 정수의 정밀도가 조용히 깨집니다 (`8143661439548533232` → `8143661439548533000`).
- 형식이 어긋난 JSON 은 손대지 않습니다.

**미리보기는 늘 정돈해 보여 주고, 파일은 설정을 켰을 때만 손댑니다.**
설정 › 일반 › *저장할 때 정돈* 에 두 가지가 있고 둘 다 기본은 꺼짐입니다.
아무것도 켜지 않으면 **쓴 그대로** 저장합니다.

- **줄 끝 공백과 문서 앞뒤의 빈 줄 지우기** — 줄 끝의 공백·탭을 지우고 문서 앞뒤의
  빈 줄을 걷어낸 뒤 줄바꿈 하나로 끝맺습니다. 뜻을 가진 공백은 남깁니다.
  마크다운에서 줄 끝의 공백 둘 이상은 줄바꿈이고, YAML 블록 스칼라 안쪽은 내용입니다.
- **문서 형식에 맞춰 들여쓰기 다시 잡기** — JSON·XML 의 들여쓰기를 맞추고,
  YAML 은 들여쓰기의 탭만 공백으로 바꿉니다.

정돈은 **그 문서에서 벗어날 때** 한 번만 합니다. 글을 쓰는 도중에 손대면 커서가 튑니다.

**XML 도 미리보기에서 들여쓰기를 맞춥니다.** 파일은 위 설정을 켰을 때만 바뀝니다.

- `DOMParser` 로 읽고 다시 써 내지 않습니다. 그러면 실체 참조가 풀리고
  빈 요소가 `<a/>` 로 접히는 등, 원문에 있던 것이 조용히 바뀝니다.
  JSON 때와 같이 글자는 그대로 두고 줄과 들여쓰기만 새로 잡습니다.
- **글이 태그와 섞인 요소는 통째로 한 줄에 둡니다.** `<p>앞 <b>강조</b> 뒤</p>`
  를 여러 줄로 펴면 없던 공백이 생겨 뜻이 달라집니다.
  `xml:space="preserve"`, CDATA 도 마찬가지로 손대지 않습니다.
- 짝이 맞지 않는 XML 은 원문 그대로 보여 줍니다.

**YAML 은 깊이를 다시 잡지 않되, 들여쓰기의 탭은 공백으로 바꿉니다.**

- 깊이를 다시 잡는 일은 하지 않습니다. YAML 은 들여쓰기가 곧 뜻이라, 다시 잡는다는
  것은 문서를 다르게 읽겠다는 말입니다. JSON·XML 과 달리 "어긋난 들여쓰기" 라는
  것이 아예 없습니다.
- 다만 **들여쓰기의 탭은 규격이 금합니다.** 탭으로 들여쓴 YAML 은 보기에만
  그럴듯할 뿐 어떤 도구로 읽어도 오류가 납니다. 그래서 이것은 모양을 다듬는 일이
  아니라 깨진 것을 고치는 일입니다. 미리보기에서는 늘 고쳐 보여 주고,
  파일은 *형식에 맞춰 들여쓰기 다시 잡기* 를 켰을 때 함께 고칩니다.
- 탭 하나를 정해진 폭으로 바꾸므로 깊이의 앞뒤 관계는 그대로입니다.
  YAML 에서 뜻을 가르는 것은 절대 칸 수가 아니라 서로 간의 깊이입니다.
- 값 안의 탭(`이름: 가<탭>나`)과 블록 스칼라(`|`, `>`) 안쪽은 내용이므로
  손대지 않습니다.

> **HTML 은 그리지 않고 글로 보여 줍니다.** 전에는 스크립트와 이벤트 속성을 걷어낸 뒤
> 아무 권한도 없는 `sandbox` iframe 안에서 그렸습니다. 그런데 스크립트로 화면을 짓는 문서나
> 폼·숨은 칸이 대부분인 문서는 그려 봐야 **빈 쪽처럼** 보입니다. 무엇이 들었는지 알려면
> 코드를 보는 편이 낫고, 정말 그려 볼 일이면 브라우저로 그 파일을 열면 됩니다.
> 문서 내용이 곧 코드가 되는 위험도 함께 사라집니다.

검색은 이런 파일의 **본문까지 훑습니다.** 아래 *검색* 을 보세요.
- 첨부 해시는 크기와 수정 시각이 그대로면 다시 계산하지 않습니다.
  그러지 않으면 회차마다 이미지를 전부 다시 읽어야 합니다.

### 파일 넣기

사이드바의 **＋ 파일** 을 누르면 파일 고르기 창이 열립니다.

- 지금 고른 폴더에 들어갑니다. 문서를 보고 있었다면 그 문서가 있는 폴더입니다.
- **밖에서 쓴 마크다운(`md`)도 그대로 넣을 수 있습니다.** 넣으면 첨부가 아니라
  문서로 열려, 곧바로 고치고 위키링크로 이을 수 있습니다.
- **컴퓨터에서 파일을 끌어다 왼쪽 트리에 놓아도 됩니다.**
  폴더 위에 놓으면 그 폴더로, 문서 위에 놓으면 그 문서가 있는 폴더로,
  빈 곳에 놓으면 최상위로 들어갑니다. 트리 항목을 끌어 옮기는 동작과는 구분됩니다.
- **다른 곳에서 문서를 열면 트리의 그 줄을 보이는 자리로 끌어옵니다.**
  백링크·위키링크·검색·즐겨찾기·동기화 결과에서 열었을 때, 그 줄이 위나 아래로
  숨어 있으면 어디가 열렸는지 알 수 없습니다. 이미 보이는 줄은 건드리지 않습니다.
- 트리에서 **폴더를 고르면** 오른쪽에 그 폴더를 위한 넣기 자리가 나옵니다.
  끌어다 놓거나 눌러서 고를 수 있고, 폴더의 항목 수와 크기도 함께 보여 줍니다.
  받는 확장자를 모두 나열해 보여 줍니다.
  여기서 넣으면 이어서 더 넣을 수 있도록 폴더 화면에 그대로 머무릅니다.
- 고르기 창에서 위 목록의 형식만 보입니다. 그래도 다른 형식을 고르면 건너뛰고 알려 줍니다.
- **같은 이름이 있으면 덮지 않고** `설계도 (2).svg` 처럼 번호를 붙입니다.
- 크기 제한을 넘는 파일도 폴더에는 들어가지만 동기화되지 않는다고 알려 줍니다.

## 아래쪽 정보 표시줄

문서·첨부·폴더 중 무엇을 골랐든 아래 한 줄에 정보가 나옵니다.

- 종류(**마크다운 · 이미지 · 문서 · 폴더**), **연 폴더 이름까지 붙인 경로**, 크기, 수정 시각.
  종류는 색으로도 구분합니다.
  `내 위키/회사/온보딩.md` 처럼 맨 앞에 지금 열어 둔 폴더 이름이 섭니다.
  폴더를 여럿 오갈 때 어느 쪽 것인지 알아야 하기 때문입니다
- **경로를 누르면 클립보드에 복사합니다.** 복사한 뒤 "파일 경로를 클립보드에
  복사했습니다" 라고 알려 줍니다. 긴 경로를 손으로 골라 잡는 것은 번거롭습니다

> 디스크의 절대 경로(`/Users/…`)까지는 붙일 수 없습니다. 브라우저가 폴더 손잡이에
> 그 값을 내주지 않기 때문입니다. 우리가 아는 가장 바깥이 이 폴더 이름입니다.
- 본문이 길어 화면이 넘쳐도, 내용이 짧아도 **늘 아래쪽에 붙어 있습니다**
- 폴더도 파일과 **같은 차례로** 크기 · 수정 시각을 늘어놓고, 그 앞에 **항목 수**만
  더 붙습니다. 고른 것에 따라 자리가 바뀌면 눈이 매번 다시 훑어야 하기 때문입니다
- 폴더의 **항목 수**는 하위 폴더와 그 안의 파일까지 셉니다. 폴더도 눈에 보이는
  한 줄이므로 셈에서 빼지 않습니다
- 폴더의 **수정 시각**은 안에서 **가장 최근에 고친 때**입니다. 폴더 자체에는
  고친 시각이 없어, 안엣것 중 가장 나중 것을 끌어올려 적습니다
- 값 사이는 **가운데 점**으로 가릅니다. 빈칸만으로는 `항목 2개 159 B` 가 한 덩어리로
  읽힙니다. 앞에 선 값이 있을 때만 붙으므로, 시각이 없는 빈 폴더에서도 점이 남지 않습니다
- **손을 얹으면 무엇인지 짧게 밝힙니다** — `폴더 크기` · `파일 크기` ·
  `최종 수정일시` · `하위 항목 개수`. 손을 얹은 채 긴 문장을 읽고 있을 사람은 없습니다.
  시각은 **마지막으로 고친 때**입니다 — 만든 시각은 브라우저가 파일에서 내주지
  않아 적을 수 없습니다
- **목차 · 백링크 · 맨 위 · 맨 아래는 본문 오른쪽 아래에 떠 있습니다.**
  긴 글을 읽다 목차를 부르려면 눈이 맨 아래 표시줄까지 내려가야 했습니다.
  글 옆에 두면 읽던 자리에서 손이 닿습니다. 두 줄로, 위에 이름(과 아이콘)
  아래에 셈이 섭니다.
  글과 표시줄에서 24px 씩 띄웁니다. **굴림대가 자리를 차지하는 기계에서는 그 너비를
  더해** 눈에 보이는 틈이 같게 합니다 — 그러지 않으면 단추가 굴림대에 달라붙습니다

**맨 위 · 맨 아래**는 **굴릴 것이 있을 때만** 나옵니다. 마크다운뿐 아니라
`txt · csv · tsv · xml · yml` 같은 글 문서, **워드(`docx`) · 엑셀(`xlsx`)** 미리보기까지
어디서나 같은 자리에서 씁니다. 한 화면에 들어오는 짧은 글에서는 나오지 않습니다 —
눌러도 아무 일이 없을 단추를 세워 둘 까닭이 없습니다.

- 굴릴 칸은 **잴 때마다 다시 찾습니다.** 보기 모드를 바꾸면 결과 칸이 헐리고 편집기가
  서고, 워드·엑셀은 벌을 내려받아 그린 **뒤에야** 결과 칸이 생깁니다. 한 번 잡아 둔 칸을
  붙들고 있으면 그 뒤로는 아무것도 재지 못해 단추가 사라진 채로 남습니다
- **목차는 편집만 보기에서도 나옵니다.** 결과 화면이면 앵커로, 편집기면 글자 자리로
  그 줄을 찾아갑니다([목차와 앵커](#목차와-앵커))
- 마크다운이 아닌 것을 골라 **부를 단추가 사라지면 펼쳐 둔 칸도 함께 접습니다** —
  접을 단추가 없는데 펼친 것만 남으면 닫을 길이 없습니다

**펼친 칸은 화면의 25%, 많아야 400px 까지만 찹니다.** 짧은 목록은 제 내용만큼만 서고, 긴 것만
그 자리에서 잘려 안에서 굴러갑니다. 40% 로 두었더니 제목이 서른 개만 넘어도 화면의 절반
가까이가 목차로 덮여 정작 글이 몇 줄 안 보였습니다. 아주 높은 화면에서는 25% 도 한참이라
400px 에서 한 번 더 묶습니다. 재는 값은 `vh` 가 아니라 `dvh` 입니다 — `vh` 는 늘 주소줄이
접힌 큰 키라, 손전화에서 주소줄이 펴져 있는 동안에는 제 몫보다 많이 덮습니다.

> **백링크**는 이 문서로 `[[링크]]` 를 건 다른 문서 목록입니다.
> 위키에서 "무엇이 이 문서를 참조하고 있나" 를 거꾸로 찾아보는 기능입니다.

목록에는 **볼트 안 전체 경로**를 적습니다. 이름만 적으면 `README.md` 처럼 폴더마다
같은 이름이 있는 문서를 구별할 수 없고, 링크가 등장한 줄까지 같으면 한 문서가 두 번
나온 것처럼 보입니다. 눈이 이름을 먼저 잡도록 앞의 폴더는 흐리게 둡니다.

단추에 적히는 **백링크 셈은 펼친 목록과 같은 자리에서 나옵니다.** 예전에는 셈만 따로
세면서 `[[링크]]` 의 **파일명만** 맞춰 보았습니다. 그래서 같은 이름의 문서가 여러 폴더에
있으면(`README.md` 처럼) 실제로는 다른 문서를 가리키는 링크까지 제 것으로 세어, 가리키는
문서가 하나도 없는데 큰 수가 적히곤 했습니다. 지금은 목록을 짓는 쪽과 같은 셈을 씁니다 —
링크를 실제 문서로 풀어 보고, 코드 블록 안의 `[[링크]]` 는 빼고 셉니다.

## 폴더를 다시 훑을 때

파일을 넣거나 이름을 바꾸거나 지우면 폴더를 다시 훑어 트리를 맞춥니다. 이때 **크기와
수정 시각이 그대로인 문서는 본문을 다시 읽지 않고** 지난 색인의 것을 그대로 씁니다.
예전에는 매번 문서 수백 개의 본문을 도로 읽어, 특히 손전화에서는 파일 하나를 넣고도
목록이 한참 뒤에야 바뀌었습니다. 바뀐 것을 놓치지는 않습니다 — 크기나 시각이 하나라도
다르면 다시 읽습니다(`scanVault` 의 `previous`).

## 폴더를 열어 둔 채 떠나면 묻습니다

폴더를 열어 둔 상태에서 새로 고침하거나 탭을 닫으면 브라우저가 **떠날지 묻습니다**(취소 /
새로 고침). 손전화에서는 화면을 아래로 당기기만 해도 새로 고침이 되어 보던 자리를 잃고 폴더
권한부터 다시 받아야 했습니다. 브라우저가 띄우는 창이라 글귀는 정할 수 없고, 사람이 한 번은
페이지를 만진 뒤에만 뜹니다. 취소하면 아무 일도 없습니다. 폴더를 열지 않았을 때는 잃을 것이
없으니 묻지 않습니다.

## 새로 고침하면 "다시 열기" 화면이 나오는 까닭

브라우저는 폴더 손잡이를 저장소에 남겨 두지만, 다시 열 때 **읽고 쓸 권한은 사람의 클릭이
있어야만 다시 받을 수 있습니다**(`requestPermission` 은 사용자 동작 없이는 거절됩니다).
그래서 새로 고침 뒤에는 폴더 이름과 **다시 열기** 단추가 있는 화면이 먼저 뜹니다.
폴더 안 파일을 읽는 일(즐겨찾기 파일 등)은 손잡이가 붙었을 때가 아니라 **폴더를 다 읽은
뒤**에 합니다 — 손잡이가 붙자마자 읽으면 권한이 없어 실패하고, 그 뒤로 다시 읽지 않아
안드로이드에서는 즐겨찾기가 늘 비어 보였습니다.
데스크톱 크롬은 한 번 허락한 뒤로 다음 방문에도 `granted` 로 답해 주는 일이 많아 곧바로
열리지만, 안드로이드 크롬은 방문마다 다시 묻습니다. 앱이 우회할 길은 없고, 한 번 누르면
지난번 열어 둔 문서까지 그대로 돌아옵니다(마지막 화면 상태).

## 배포

빌드 결과물은 그냥 정적 파일이라 아무 정적 호스팅에나 올리면 됩니다.
**Cloudflare Pages** 를 씁니다. 대역폭과 정적 요청이 무제한이고, HTTPS 가 자동으로 붙습니다.

저장소를 연결하고 아래만 넣으면 끝입니다.

| 칸 | 값 |
| --- | --- |
| 프레임워크 사전 설정 | 없음 (None) |
| 빌드 명령 | `npm run build` |
| 빌드 출력 디렉터리 | `dist` |

`.node-version` 에 22.12.0 을 못 박아 두었습니다. Vite 8 은 20.19 이상을 요구하는데
빌드 기계의 기본 Node 가 그보다 낮으면 여기서 엎어집니다.

`index.html` 끝에 **Cloudflare Web Analytics** 조각이 들어 있습니다. 방문 수만 세는
가벼운 조각이라 쿠키를 쓰지 않습니다. 토큰은 페이지에 그대로 실리는 값이라 감출 것이
아닙니다. 다만 이 조각은 앱과 같은 오리진에서 도므로, **원리상 이 오리진의 저장소
(액세스 토큰이 든 IndexedDB)를 읽을 수 있습니다.** 남의 코드를 페이지에 들이는 일이
늘 그렇습니다. 통계가 필요 없어지면 그 두 줄을 지우면 그만입니다.

`public/_headers` 에 응답 머리말을 적어 두었습니다. 이 앱은 액세스 토큰을 브라우저에
들고 있으므로 남의 페이지 안에 끼워 넣지 못하게 막고(`X-Frame-Options: DENY`,
`frame-ancestors 'none'`), 바깥으로 새는 정보를 줄입니다.
파일 이름에 내용 해시가 붙는 `assets/` 는 오래 물려 둡니다.

**CSP(Content-Security-Policy)로 이 오리진에서 도는 코드를 우리가 올린 것으로 묶습니다.**
어디선가 스크립트 한 줄이 끼어들어도 실행되지 않고, 나가는 곳도 GitHub API 로 좁혀 둡니다.
토큰이 든 오리진이라 이 울타리의 값이 큽니다.

| 갈래 | 왜 그렇게 두었나 |
| --- | --- |
| `script-src 'self' …cloudflareinsights.com` | 우리 번들과 통계 조각만. `unsafe-inline` 은 두지 않습니다 |
| `connect-src 'self' api.github.com …` | 토큰을 들고 나갈 수 있는 곳을 좁힙니다 |
| `img-src 'self' blob: data:` | 볼트 안 그림은 blob URL 로 그립니다 |
| `style-src 'self' 'unsafe-inline'` | 화면 곳곳의 인라인 스타일과 mermaid 가 넣는 스타일. 문서 안 `<style>` 은 앱이 걷어냅니다 |
| `font-src 'self' data:` | KaTeX 글꼴 한 벌이 작아 CSS 안에 박혀 나옵니다 |
| `frame-src 'self' blob:` | PDF 미리보기가 blob URL 을 씁니다 |
| `object-src 'none'` · `base-uri 'self'` · `form-action 'none'` | 쓰지 않는 길은 아예 닫습니다 |

CSP 는 어긋나도 조용히 깨집니다. 그래서 `csp` 시험 묶음이 **빌드 결과에 이 머리말을
실제로 붙여 띄우고** 그림·다이어그램·수식·오피스 미리보기·동기화가 모두 되는지, 막힌 것이
하나도 없는지 확인합니다. 머리말은 이 파일에서 그대로 읽어 오므로 따로 적어 둔 사본이
어긋날 일이 없습니다.

> **HTTPS 가 아니면 동작하지 않습니다.** 폴더를 고르는 API 는 보안 맥락에서만 열립니다.
> `localhost` 는 예외로 열리지만, 다른 기기에서 `http://192.168.…` 로 들어오면 폴더를
> 아예 고를 수 없습니다. `file://` 로 여는 것도 같은 이유로 막힙니다.

하위 경로로 서비스하는 곳(GitHub Pages 의 `사용자.github.io/저장소/`)에 올릴 때는
`BASE_PATH=/저장소이름/ npm run build` 로 빌드합니다.

## GitHub 동기화

**설정과 기준점은 폴더마다 따로 둡니다.** 액세스 토큰도 마찬가지입니다.
처음 보는 폴더를 열면 토큰까지 모두 비어 있고, 그 폴더에 맞춰 둔 적이 있으면
그때 넣어 둔 토큰이 그대로 들어와 있습니다. 같은 폴더인지는 이름이 아니라 핸들로
가려내므로, 이름이 같은 다른 폴더와 섞이지 않습니다.

설정 › 일반 › *설정 주고받기* 에서 **내보내기·가져오기** 를 할 수 있습니다.
내보내기는 **내려받기 폴더로 흘려보내지 않고, 저장할 자리를 골라 곧바로 씁니다.**
이 앱은 이미 폴더 손잡이로 파일을 다루므로 설정 파일도 같은 길로 나갑니다.
모양(테마·모드·글꼴·크기·너비), 저장 방식, 마지막 상태 기억,
이미지 미리보기와 그 바탕, 오피스 미리보기,
옆줄 접힘·너비·고른 탭, 나란히 보기의 몫, 토큰 포함 여부와
**지금 열려 있는 폴더**의 저장소 설정을
파일 하나로 담습니다.
브라우저에 남는 취향은 하나도 빠짐없이 들어갑니다.
다른 기기에서는 폴더를 먼저 연 뒤 가져오면 그 폴더에 들어갑니다.

- **액세스 토큰은 기본으로 담지 않습니다.** 담으려면 따로 켜야 합니다.
- **담을 때는 암호를 받아 잠급니다.** 브라우저 안의 열쇠로 봉한 것은 다른 기기에서 풀 수
  없으므로, 파일에는 사람이 아는 암호에서 끌어낸 열쇠(PBKDF2-SHA-256 310,000회 → AES-GCM 256)로
  잠근 것만 적습니다. 글자 그대로 적는 길은 없습니다 — 암호를 넣지 않으면 파일도 만들지
  않습니다. 잠갔더라도 그 토큰으로 저장소를 읽고 쓸 수 있으니 메일이나 채팅으로 주고받지
  마세요.
- **암호는 두 번 받아 맞춰 봅니다.** 가려서 받으므로 오타를 눈으로 잡을 수 없고, 잘못 친
  암호로 잠근 파일은 누구도 풀지 못합니다. 둘이 다르면 처음부터 다시 받습니다.
- **가져올 때는 같은 암호를 묻습니다.** 틀리면 남은 횟수를 알리며 다시 묻고, **세 번 틀리면
  가져오기를 접습니다** — 아무것도 바꾸지 않은 채 파일부터 다시 고르게 합니다(암호는 무엇이든
  적용하기 전에 먼저 받습니다). 물러서면(취소) **토큰만 빼고** 나머지 설정을 들여옵니다.
  토큰 하나 때문에 나머지까지 버릴 까닭은 없습니다. 이때 여기 있던 토큰은 지우지 않습니다.
  옛 판에서 만든, 토큰이 글자 그대로 적힌 파일도 그대로 받습니다.
- **잊은 암호는 되찾을 길이 없습니다.** 암호는 어디에도 적히지 않습니다. 토큰만 빼고 들여온 뒤
  설정에서 토큰을 다시 넣거나, 원래 브라우저에서 새 암호로 다시 내보내면 됩니다.
- **열어 둔 폴더 안에 저장하려 하면 한 번 더 묻습니다.** 그 자리에 두면 설정 파일도
  동기화 대상이 되어, 토큰이 담긴 채로 저장소에 올라갑니다. 올라간 토큰은 커밋 기록에
  남아 지워도 되돌리기 어렵습니다. 물러서면 저장 창이 만들어 둔 빈 파일까지 치웁니다.
  그래도 저장하면, 저장소로 올라간다는 것을 붉은 글씨로 알려 줍니다.
- 저장소 설정이 든 파일을 가져오면 **자동 동기화 차례를 새로 잡습니다.** 잡아 두었던
  차례는 버리고 가져온 간격에서 처음부터 셉니다. 켜짐 여부와 간격이 우연히 같아도
  그렇습니다. 대상이 달라졌는데 앞 설정으로 세던 시간이 이어지면, 화면에 뜬 남은 시간이
  어느 저장소를 향한 것인지 알 수 없습니다.
- 내보내기·가져오기는 **확인을 한 번 받고** 진행합니다. 무엇이 담기는지, 토큰이 실리는지
  밝히고 묻습니다. 가져오기는 파일을 읽은 뒤에 묻습니다. 고르기 전에 물으면 무엇이
  들었는지 모른 채 답해야 합니다.
- **동기화 기준점은 담지 않습니다.** 기준점은 그 폴더가 저장소와 어디까지 맞췄는지이고
  기기마다 다릅니다. 남의 기준점을 들여오면 여기 없는 파일이 지워진 것으로 읽힙니다.
- 폴더 손잡이도 담지 않습니다. 브라우저 밖에서는 뜻이 없는 값입니다.

설정 › GitHub 동기화에 **마지막 동기화 시각**이 있고, 그 옆에 **마지막으로 올린 커밋**의
이름이 붙습니다. 누르면 GitHub 의 그 커밋 화면이 새 탭으로 열립니다.

- 올릴 것이 없는 동기화는 커밋을 만들지 않습니다. 그때는 시각만 새로 적히고
  커밋 이름은 지난 것이 그대로 남습니다.
- 시각과 커밋 이름 모두 **폴더마다 따로** 두고 새로고침해도 남습니다.
- 저장소를 아직 고르지 않았거나 이 폴더의 설정을 지운 뒤에는 주소를 지을 수 없으므로
  링크를 내보내지 않습니다.

### 오간 줄을 그리는 격자

한 항목이 **두 줄 한 벌**입니다 — 윗줄에 갈래와 경로, 아랫줄에 까닭과 커밋.

- 셋을 한 줄에 두었더니 **경로가 길 때 제 칸 안에서 여러 줄로 접혀**, 줄마다 높이가 들쑥날쑥하고
  어디까지가 한 항목인지 눈으로 끊기 어려웠습니다. 칸에 바닥(12ch)을 두어 보았지만 그것은
  경로가 한 글자씩 세로로 쌓이는 것을 막을 뿐, 접히는 것 자체는 그대로였습니다.
  **늘 두 줄이면 보이는 줄 수는 줄지만 결이 고르고, 경로도 까닭도 폭을 다 씁니다.**
- 아랫줄은 **한 단 작게**(11px) 둡니다. 읽어야 할 것은 경로이고 까닭과 커밋은 곁들임입니다.
- 성공한 줄과 실패한 줄의 **생김이 같아집니다.** 전에는 오류 줄만 두 줄이라 결이 달랐습니다 —
  이제 다른 것은 **글씨 색뿐**입니다.

### 실패한 줄과 멈춘 회차에 적는 것

실패한 줄의 까닭이 성공한 줄의 `로컬에서 수정` 과 **똑같이 흐린 색**이었습니다. 갈래 딱지만
붉고 정작 읽어야 할 글이 흐린 것은 거꾸로라, 무엇이 왜 실패했는지가 눈에 들어오지
않았습니다. 이제 **실패한 줄의 까닭은 붉게** 적습니다.

- **테두리나 바탕을 두르지 않습니다.** 칸을 만들어 보았더니 한 줄짜리 까닭에 견주어 요란했고,
  목록의 결도 끊겼습니다. 글씨 색만으로 넉넉합니다.
- **받아 온 숫자를 글 끝에 붙입니다**: `… could not be found … (404 Not Found)`. 긴 영어 문장만
  남으면 404 인지 권한 문제인지 가릴 수 없습니다. 숫자가 없는 때(답이 아예 오지 않은 때)는
  글만 남습니다 — 없는 것을 지어내지 않습니다.
- 아예 멈춘 회차(오간 줄이 없는 회차)는 `오간 것 없이 멈췄습니다.` 뒤에 **까닭을 붉게** 잇고,
  받아 온 것이 있으면 괄호로 덧붙입니다: `(404 Not Found · GET /repos/… · 요청번호)`.
  GitHub 요청 번호는 문의할 때 그 하나면 그 요청을 찾아 줍니다.
- 숫자를 남기려면 던지는 쪽부터 고쳐야 했습니다. 글만 던지면 GitHub 이 `message` 를 줄 때
  그 글이 상태 코드를 덮어 숫자가 사라집니다. `GitHubRequestError` 가 글과 숫자(상태·요청·요청
  번호)를 함께 들고 오고, `describeFailure` 가 그것을 한 꼴로 추립니다.

### 지난 결과 보기

설정 › GitHub 동기화의 **지난 결과 보기** 는 이 폴더에서 돈 동기화를
**최근 100건까지** 늘어놓습니다. 한 번도 돌린 적이 없으면 눌리지 않습니다.

- 한 줄에 **시각 · 직접/자동 · 요약**이 섭니다. 요약은 `올림 3 · 내려받음 1 · 지움 2`
  처럼 갈래별 건수이고, 실패가 있으면 빨갛게, 오간 것이 없으면 `변화 없음` 입니다.
- 회차를 누르면 그 회차에 **오간 파일 목록**이 펴집니다. 한 번에 한 회차만 펴 둡니다.
- **경로는 마디마다 눌립니다.** `/회사/온보딩.md` 에서 *회사* 를 누르면 그 폴더가,
  *온보딩.md* 를 누르면 그 문서가 열립니다. 어느 쪽이든 겹쳐 뜬 창이 모두 닫힙니다.
  한 겹만 걷으면 방금 연 것이 그 뒤에 가려, 눌렀는데 아무 일도 없는 것처럼 보입니다.
  폴더로 가면 트리에서도 그 자리가 펴집니다.
- 지운 줄에서는 **파일 이름에 길을 걸지 않습니다.** 열 것이 없습니다.
  담고 있던 폴더는 남아 있으므로 폴더 마디는 그대로 눌립니다.
  그 사이에 사라진 파일이나 폴더면 창을 그대로 두고 알리기만 합니다.
- 파일 한 줄에 `갈래 · 경로 · 까닭` 이 나란히 서고, 저장소에 올라간 줄은 까닭 끝에
  **그 커밋 이름**이 붙습니다. 누르면 GitHub 의 그 커밋이 새 탭으로 열립니다.
  그래서 커밋 하나짜리 회차는 머리줄까지 **두 줄**로 끝납니다.
- 자동 동기화를 켜 두면 `변화 없음` 이 목록을 채웁니다.
  **무언가 오간 회차만 보기** 로 걸러 봅니다.
- 목록 자리는 **열 줄쯤**으로 잡아 둡니다. 그보다 많으면 그 안에서 굴려 봅니다.
  회차를 펼 때마다 창이 늘었다 줄었다 하지 않습니다.
- 100건을 넘으면 오래된 것부터 버립니다. 한 회차에 남기는 줄도 200줄까지입니다.
  첫 동기화처럼 몇천 줄짜리 회차 하나가 나머지 아흔아홉 건보다 무거워지지 않게 합니다.
- **폴더마다 따로** 두고 새로고침해도 남습니다. 이 폴더의 설정을 지우면 함께 지워집니다.

창 발치의 **자세히 보기** 는 GitHub 의 커밋 목록
(`https://github.com/<소유자>/<저장소>/commits/<브랜치>/`)을 새 탭으로 엽니다.
하위 폴더를 정해 두었으면 그 아래 커밋만 추려 갑니다. 여기 목록은 이 브라우저가
돌린 회차만 알지만, 저장소에는 다른 기기와 다른 사람이 올린 것까지 모두 있습니다.

설정 › GitHub 동기화 아래쪽에 **이 폴더의 설정 지우기** 가 있습니다.
지금 열려 있는 폴더의 저장소 설정과 토큰만 지우고, 다른 폴더는 건드리지 않습니다.

폴더를 **가려내지 못하면 표를 새로 매기지 않습니다.** 가려내지 못하는데 표를 매기면
이미 표가 있는 폴더에 표가 하나 더 생기고, 같은 폴더가 둘로 갈려 맞춰 둔 설정이
사라진 것처럼 보입니다.

> 예전에는 설정이 한 벌뿐이었습니다. A 폴더를 어떤 저장소에 맞춰 두고 B 폴더를 열면
> B 가 A 의 설정과 A 의 기준점을 그대로 물려받았고, 그 상태로 동기화하면 A 의 파일들이
> B 에 없으니 "지워졌다" 로 읽혀 **저장소에서 모두 사라졌습니다.**
 설정

문서를 GitHub 저장소와 양방향으로 맞춥니다. 브라우저에서 GitHub REST API 를 직접 부르므로
중간 서버가 없고, 저장할 때마다 커밋이 남아 히스토리와 되돌리기가 공짜로 딸려옵니다.

### 붙이는 법과 그 까닭

토큰을 발급해 앱에 넣고 저장소를 고르는 **절차는 [USAGES.md 의 GitHub 동기화](USAGES.md#github-동기화)**
에 있습니다. 여기에는 왜 그 방식인지만 적습니다.

- **PAT(Fine-grained personal access token) 을 씁니다.** OAuth App 은 client secret 교환이
  필요해 서버 없는 정적 앱에서 쓸 수 없고, device flow 는 토큰 교환 엔드포인트가 `github.com`
  도메인이라 브라우저에서 직접 부를 수 없습니다. 남는 길이 PAT 이고, 대신 발급 안내에서
  **저장소 하나 · Contents 읽기/쓰기 · 만료일**로 범위를 좁히도록 이끕니다. 새어 나가도
  피해가 그 저장소 하나에 갇히게 하는 것이 핵심입니다.
- **토큰이 잘못되면** 칸 바로 아래에 알리고, 입력란과 저장된 값을 비우며 **앞서 띄워 둔
  계정·저장소 목록도 거둡니다.** 그 목록을 그대로 두면 이번 토큰이 통한 것으로 읽혀, 잘못된
  토큰인 줄 모르고 저장소를 고르게 됩니다. 저장소·브랜치 설정은 손대지 않습니다.
- 확인이 끝나면 입력란은 사라지고 `**********` 만 남깁니다 — 값이 **있다는 것만** 알립니다.
- **동기화 직전에 편집 중이던 내용을 먼저 파일에 저장합니다.** 그러지 않으면 방금 친 글자가
  내려받은 내용에 덮입니다.
- 실패하거나 문제가 있으면 자세한 결과 창이 저절로 열립니다. 올라간 줄의 커밋 이름을 누르면
  GitHub 의 그 커밋으로, 파일 이름을 누르면 그 파일로 갑니다.

### 도는 동안 보이는 것

단추 안의 막대가 몇 할인지를 채우고, **단추 바로 아래에 진행 창**이 붙어 무엇을 옮기고
있는지 적습니다 — 제목(비교하는 중 · 동기화하는 중), 막대와 `6/12` 같은 셈, 그리고
`올리는 중 메모 6.md` 처럼 **지금 다루는 파일과 방금 지난 파일 넉 줄**(최근 것이 위).
몇 할인지 모르는 단계(비교하는 중)에서는 막대가 흐릅니다. 도는 동안만 뜨고 끝나면 스스로
걷히며, 덮개도 닫기 단추도 없습니다. 자리는 단축키 목록처럼 화면 폭에 맞춥니다.

### 자동 동기화

**정해진 간격마다 알아서 동기화하기** 를 켜면 정기적으로 동기화합니다.

- 간격은 분 단위로 입력합니다. **기본값은 10분** 이고 1분에서 1440분(하루)까지 정할 수 있습니다.
- 켜져 있으면 정한 간격마다 반복합니다. 폴더를 열자마자 도는 첫 회차는 없습니다.
- **폴더를 읽는 동안에는 돌지 않습니다.** 단추는 잠기고, 단축키나 설정의 실행 단추로 불러도
  "읽는 중"이라고만 알립니다. 자동 회차는 조용히 건너뛰고 다음 차례를 기다립니다. 반쯤 읽힌
  색인으로 돌면 아직 안 읽은 파일이 "로컬에서 사라짐"으로 잡혀 저장소에서 지워지거나 도로
  내려받힙니다. 손전화처럼 느린 기기에서는 읽는 데 한참 걸려 그 틈이 넓습니다.
- **타자 도중이면 손을 뗀 지 2초가 지나기를 기다렸다가 저장하고 돕니다.** 치는 도중에 돌면
  반쯤 쓴 글이 커밋됩니다. 계속 치고 있으면 20초까지만 기다리고 그대로 갑니다 —
  마냥 미룰 수는 없습니다. 직접 누른 회차는 기다리지 않습니다.
- 이미 동기화 중이면 그 회차는 건너뜁니다. 겹쳐 도는 일은 없습니다.
- **탭을 여러 개 열어도 한 번에 하나만 돕니다.** 브라우저 잠금으로 막고,
  직접 누른 경우에는 "다른 탭에서 동기화 중입니다" 라고 알려 줍니다.
- 실행 직전에 설정을 저장소에서 다시 읽습니다.
  다른 탭에서 바꾼 설정이 이 탭에 반영되지 않아 서로의 결과를 되돌리는 일을 막습니다.
- 저장소 조회는 **브라우저 캐시를 건너뜁니다.** GitHub 이 인증된 응답에도
  `cache-control: private, max-age=60` 을 붙이는데, 그대로 두면 방금 우리가 옮겨 놓은
  브랜치 위치를 최대 1분간 못 보고 낡은 부모 위에 커밋을 쌓다가 계속 거절당합니다.
- 커밋 직전에 저장소가 바뀌어 거절당하면(다른 기기·웹 편집·git push 등)
  **저장소를 다시 읽고 계획을 새로 세워 최대 3번까지 시도합니다.**
  `git pull --rebase && git push` 와 같은 동작이고, 실패로 표시되지 않습니다.

### 동기화 대상을 바꿀 때

비교 기준점은 **저장소·브랜치·하위 폴더 조합마다 따로** 보관합니다(최근 5개).
그래서 하위 폴더를 바꿨다가 되돌리면 예전 기준점이 그대로 다시 쓰입니다.

대상을 바꾸면 문서가 올라갈 경로가 통째로 달라지므로, 그 대상으로 처음 동기화할 때는
**바로 실행하지 않고 무엇이 오갈지 먼저 보여 줍니다.**

- 같은 문서에 대해 *커밋(신규)* 과 *내려받기(신규)* 가 함께 보이면,
  옛 경로와 새 경로 양쪽에 같은 내용이 생긴다는 뜻입니다. 의도한 게 아니면 취소하세요.
- **이대로 진행** 을 누르면 그 대상은 다음부터 묻지 않습니다.
- 켜져 있는 동안 상단에 **다음 실행까지 남은 시간**이 `04:32` 처럼 1초마다 줄어듭니다.
  새로고침하거나 폴더를 다시 열면 **정해 둔 간격에서 처음부터** 다시 셉니다.
  폴더마다 맞춰 둔 저장소가 다르므로 앞 폴더에서 세던 시간을 이어 가지 않습니다.
  폴더를 열자마자 자동으로 한 번 도는 일은 없습니다. 바로 맞추려면 단추를 누르세요.
  동기화가 도는 동안에는 `동기화 중` 으로 바뀌고, 끝나면 다시 세기 시작합니다.
- 동기화가 도는 동안 **GitHub 동기화 단추는 잠기고** 남은 시간이 `00:00` 이 됩니다.
- **직접 눌러 동기화해도 남은 시간은 처음부터 다시 셉니다.** 방금 맞춰 놓고
  몇십 초 뒤에 또 도는 일이 없습니다.
- 머리줄 단추는 아이콘과 글자를 함께 보여 줍니다. 너비는 글자에 맞추되,
  **동기화 단추만** 도는 동안 글자가 바뀌어도 너비가 그대로라 옆 단추가
  밀리지 않습니다. 진행 건수는 단추 안내에 뜨고, 얼마나 갔는지는 단추 안쪽이
  차오르며 보여 줍니다.
- 보기 모드(편집 · 나란히 · 미리보기)는 폴더마다 따로 기억합니다. 문서 제목 줄 오른쪽에
  앞에는 **보기 모드**, 단추에는 **아이콘과 이름을 함께** 세워 둡니다. 세 아이콘은
  서로 닮아 그림만으로는 눌러 봐야 알고, 같은 자리에 서는 그림 배경 고르개와도
  헷갈립니다. 보여 줄 것이 있는 문서에서만 나오고, 이미지나 폴더를 고르면 사라집니다.
- **나란히 볼 때는 가운데 손잡이를 끌어 두 칸의 몫을 바꿉니다.** 원문을 넓게 쓰다가
  결과를 넓게 보는 식으로 오갈 수 있습니다. 어느 쪽도 20% 아래로는 줄지 않습니다.
  한쪽이 사라지면 나란히 볼 까닭이 없고 손잡이도 잡을 수 없게 됩니다.
  두 번 누르면 반반으로 돌아가고, 자판으로도 옮길 수 있습니다
  (화살표는 2%, Shift 와 함께는 8%). 고른 몫은 기억하고, 마크다운과 글 첨부가 같이 씁니다.
  **잡고 있는 동안 지금 몫이 `56% : 44%` 처럼 숫자로 뜹니다.** 눈대중으로는 맞추기
  어렵기 때문입니다. 놓으면 사라집니다 — 늘 떠 있으면 글 위에 앉습니다.
  자판으로 옮길 때는 자리를 잡고 있는 동안 계속 보여 줍니다.
- **폴더를 읽는 동안 무엇을 하고 있는지 보여 줍니다.** 파일이 많으면 다 훑는 데
  한참 걸리는데, 그동안 화면이 비어 있으면 빈 폴더를 연 것처럼 보입니다.
  옆줄과 본문에 도는 고리와 함께 `폴더를 읽는 중… 1,240개` 처럼 **어디까지 왔는지
  세어** 보여 줍니다. 멈춘 것인지 나아가는 것인지는 숫자라야 압니다.
- 옆줄은 **폴더 · 즐겨찾기 두 탭**입니다. 한 번에 한 쪽만 보여 줍니다.
  좁은 칸을 둘로 나눠 쓰면 양쪽 다 몇 줄씩만 보입니다. 고른 탭은 기억하므로
  새로고침해도 보던 쪽으로 열립니다. 기본은 폴더입니다.
  **찾는 칸은 두 탭에 다 있지만 하는 일이 다릅니다.** 폴더 탭에서는 볼트 전체를,
  즐겨찾기 탭에서는 담아 둔 것만 이름으로 거릅니다.
  즐겨찾기 탭에 담아 둔 것이 없으면 왜 비었는지, 어떻게 담는지 적어 둡니다.
  새 문서·새 폴더·파일 추가·새로고침·폴더 닫기는 트리 뿌리 줄에 있으므로 폴더 탭에서 씁니다.
- 트리 맨 위에 **뿌리 줄**이 있습니다. 오른쪽에 새 폴더 · 새 문서 · 파일 추가 ·
  새로고침 · 폴더 닫기가 아이콘으로 서 있고, 손을 얹지 않아도 늘 보입니다.
  앞의 셋은 언제나 최상위를 가리킵니다. 폴더 줄에도 같은 아이콘이 같은 차례로 있고,
  그쪽은 그 폴더를 가리킵니다.
- 이름 앞 아이콘은 종류마다 색이 다릅니다. 폴더는 호박색, 마크다운은 파랑,
  이미지는 초록, 그 밖의 첨부는 무채색입니다.
- **폴더 줄은 한 번에 한 가지만 합니다.** 처음 누르면 고르기만 하고, **이미 골라 둔
  폴더를 다시 누를 때** 폈다 접습니다. 둘을 함께 걸어 두면 안을 들여다보려고 누를
  때마다 오른쪽 화면이 폴더 정보로 바뀌고, 폴더를 고르려고 누를 때마다 트리가
  접혔다 펴집니다.
  **폴더 앞 꺾쇠**는 고르기와 상관없이 폈다 접기만 합니다. 보던 문서를 그대로 둔 채
  옆 폴더 안을 들여다볼 때 씁니다. 문서 줄은 예전처럼 한 번 누르면 열립니다.
- **끌고 가다 옆줄의 위아래 끝에 닿으면 목록이 저절로 굴러갑니다.** 끝에 가까울수록
  빨라지고, 손을 놓거나 띠를 벗어나면 멈춥니다. 목록이 길면 맨 아래 것을 맨 위로
  옮길 길이 없었습니다 — 집어 든 채로는 굴림대를 만질 수 없기 때문입니다.
  즐겨찾기 차례 바꾸기에도 똑같이 걸립니다. 두 탭이 같은 굴림 칸을 씁니다.
- **끌어다 옮길 때 같은 이름이 있으면 묻습니다.** 덮어쓸지 그만둘지 고르게 하고,
  무엇이 사라지는지 창에 그대로 적습니다. 폴더를 덮어쓰면 **그 안에 든 것까지**
  사라지므로 그 말도 함께 적습니다. 예전에는 "이미 있습니다" 한 줄을 띄우고 말아,
  덮어쓰려는 사람은 옮길 길이 없고 실수로 놓은 사람은 무슨 일인지 알기 어려웠습니다.
  이름 바꾸기는 아직 예전처럼 거절합니다.
- 줄 오른쪽 별을 누르면 **즐겨찾기**에 담깁니다. 폴더도 담깁니다.
  문서가 많아지면 트리를 훑는 것보다 빠릅니다.
  **담긴 줄은 손을 얹지 않아도 그 별 단추가 켜진 채로 남아 있습니다.** 그것이 곧 표시이고,
  같은 자리를 누르면 뺍니다. 이름 앞에 별을 따로 찍지 않습니다 — 같은 뜻이 둘이 됩니다.
  나머지 단추(새 문서·이름 바꾸기·삭제 …)는 손을 얹어야 나옵니다. 별은 **맨 끝**에 있어,
  손을 얹어 다른 단추가 나와도 자리가 튀지 않습니다.
  목록은 **폴더 안 `_t-wiki.favorites.json` 에 적힙니다.** 그래서 GitHub 동기화를 타고
  다른 기기에서도 그대로 보입니다.
  **두 기기가 저마다 담아 두어 부딪히면 어느 쪽을 고르지 않고 합칩니다.** 여느 파일처럼
  한쪽을 고르거나 사본을 남기면, 한 기기에서 담은 것이 다른 기기에서는 사라진 것처럼
  보였습니다(마지막에 올린 쪽만 남음). 목록은 합쳐도 잃을 것이 없으므로, 설정한 부딪힘
  처리와 상관없이 이쪽 차례를 지키고 저쪽에만 있는 것을 뒤에 붙여 양쪽에 둡니다.
  부딪히지 않을 때(한쪽만 고쳤을 때)는 여느 파일처럼 그대로 따라가므로, 한쪽에서 빼면
  다음 동기화에서 저쪽도 빠집니다.
  **이 파일을 앱 안에서 열어 손으로 고쳐 저장하면 목록도 그 글을 따릅니다.** 트리에는
  감춰 두었지만 본문 검색이나 동기화 결과에서 열 수 있습니다. 목록으로 읽히지 않는 글
  (JSON 이 깨졌거나 배열이 아님)은 화면을 건드리지 않습니다. 트리에는 보이지 않습니다. 사람이 열어 고칠 파일이
  아니라 앱이 쓰는 살림입니다. 이름을 바꾸거나 옮기면 따라가고, 지우면 함께 빠집니다.
  **담긴 것마다 이름 아래에 어디에 있는 것인지 흐린 글씨로 한 줄 붙습니다**
  (`/기타/프로필/pikachu.jpg`). 이름만으로는 가릴 수 없는 것들이 섞이기 때문입니다.
  문서·첨부·폴더 가리지 않고 최상위에 있는 것에도 붙습니다.
  두 줄에 다 적혀 있어 줄에 손을 얹어도 툴팁은 뜨지 않습니다.
  경로가 길어 잘리면 옆줄 너비를 넓혀 봅니다.
  **줄을 끌어다 놓아 차례를 바꿉니다.** 줄의 위 절반에 놓으면 그 앞으로,
  아래 절반에 놓으면 그 뒤로 갑니다. 끼어들 자리에 금이 그어집니다.
  끌지 않고 **Shift + ↑ / ↓** 로도 옮길 수 있습니다.
  바꾼 차례는 곧바로 파일에 적혀 다른 기기에서도 그대로 보입니다.
  이름으로 걸러 본 채로 옮겨도 **가려져 있던 줄은 제자리에 남습니다.**
  자리를 번호가 아니라 경로로 가리키기 때문입니다.
  이 파일은 트리에 보이지 않지만 **동기화 결과에는 이름이 나오고, 눌러서 열 수 있습니다.**
  열면 제목 줄의 *저장됨* 옆에 **빨간 글씨로 조심하라고 적힙니다.**
  손으로 고치면 즐겨찾기가 통째로 흐트러집니다.
- 옆줄 오른쪽 모서리를 **끌어서 너비를 바꿉니다.** 240px 부터 창의 60%(최대 720px)
  까지입니다. 너무 좁으면 이름이 잘리고 너무 넓으면 본문이 없어집니다.
  두 번 누르면 처음 폭으로 돌아가고, 자판으로도 옮길 수 있습니다
  (화살표는 16px, Shift 와 함께는 48px). 고른 너비는 기억합니다.
- 탭 줄 오른쪽에 **접기·펴기 단추**가 있습니다. 접어도 칸을 아주 없애지 않고
  단추가 설 폭(52px)은 남깁니다. 아이콘은 누르면 어떻게 되는지를 가리키고,
  접은 상태는 기억합니다. **접힌 채로도 그 아래에 탭 단추 둘이 서 있어**,
  누르면 펴면서 곧바로 그 탭으로 갑니다. 펴고 나서 탭을 고르는 두 걸음이 한 걸음이 됩니다.
- 검색란에 한 글자라도 치면 안쪽 오른쪽에 **지우기 단추**가 나옵니다.
  누르면 비우고 곧바로 다시 칠 수 있게 자리를 돌려 줍니다.
- 검색 결과는 **방향키로 오르내리고 엔터로 엽니다.** 맨 위에서 더 올라가면
  검색란으로 돌아가 글자 끝에 자리를 두므로, 손을 떼지 않고 검색을 이어갈 수 있습니다.
- 두 탭의 찾는 칸은 **친 글자를 각자 들고 있습니다.** 탭을 오갔다고 해서
  찾던 말이 사라지거나 엉뚱한 쪽에 끼어들지 않습니다.
- 파일 이름은 트리·검색·제목 줄 어디서나 **확장자까지 그대로** 보여 줍니다.
  경로는 어디서나 `/` 로 시작해 최상위에서부터라는 것이 드러납니다.
- 제목 줄에는 이름만 둡니다. 경로는 아래 상태 표시줄이 늘 보여 주므로 겹칩니다.

설정과 동기화 기록은 브라우저 IndexedDB 에 저장됩니다.

### 액세스 토큰은 봉해서 둡니다

토큰을 글자 그대로 적어 두면 개발자 도구의 저장소 탭에서 그대로 읽힙니다. 그래서
**저장하는 자리에서 봉하고(AES-GCM 256) 읽는 자리에서 풉니다** — `store.ts` 의 두 함수뿐이라
앱의 다른 어디서도 봉한 꼴을 알 필요가 없고, 빠뜨릴 자리도 없습니다.

- 열쇠는 이 브라우저가 처음 봉할 때 만들어 같은 IndexedDB 에 둡니다.
  **꺼낼 수 없는(extractable: false) 열쇠**라 자바스크립트로 열쇠 자체를 읽어 낼 길은 없고,
  봉한 것을 푸는 데만 쓸 수 있습니다.
- 봉할 때마다 새 초기값(iv)을 뽑으므로 같은 토큰을 두 번 봉해도 바이트가 다릅니다.
- 예전에 글자 그대로 적어 둔 토큰은 **읽는 김에 봉해서 다시 둡니다.** 손댈 것이 없습니다.
- 열쇠가 바뀌었거나 값이 상해 풀 수 없으면 토큰만 비우고 나머지 설정은 살립니다. 다시 붙여넣으면 됩니다.

> 이것은 저장소를 들여다보는 눈에서 글자를 감추는 일이지, 브라우저 프로필을 통째로 가져간
> 사람까지 막는 일은 아닙니다. 같은 출처의 코드는 그 열쇠로 풀 수 있습니다. 그런 데까지
> 막으려면 매번 암호를 받아야 하는데, 그 값은 치르지 않기로 했습니다. 공용 PC 에서는 쓰지 마세요.

설정 파일에 든 잠근 토큰은 **적힌 값을 그대로 믿지 않습니다.** 반복 횟수는 2,000,000 까지만
받고(우리가 쓰는 310,000 의 여섯 배 남짓), salt·iv·본문 길이도 우리가 만든 그대로여야 합니다.
누가 반복 횟수를 수십억으로 고쳐 둔 파일을 들여오면 풀다가 탭이 멎는데, 그런 값은 잠근 꼴로
치지 않고 토큰만 빼고 들여옵니다.

### 문서가 앱 화면을 건드리지 못하게

- 문서 안 `<style>` 은 **걷어냅니다.** 저장소를 같이 쓰는 사람이 넣은 CSS 가 앱 화면을 덮거나
  가짜 안내를 그릴 수 있습니다. 밖으로 새 나갈 길은 CSP 가 막지만, 문서 하나가 앱의 생김새를
  바꿔서는 안 됩니다. 요소에 붙는 `style` 속성은 그 요소 안에 갇히므로 그대로 둡니다.
- 앱이 화면에서 무언가를 찾을 때(설정 갈래의 머리, 굴릴 칸, 아래 표시줄) **제 창 안에서만
  찾습니다.** 문서에 `id="set-font"` 나 `class="editor"` 같은 요소가 있어도 그쪽이 잡히지
  않습니다. `document` 전체에서 찾으면 먼저 그려진 문서 쪽이 잡혀 메뉴가 엉뚱한 곳으로 굴러갔습니다.

### 휴지통

지우면 곧바로 없애지 않고 **휴지통으로 옮길지, 완전히 지울지** 묻습니다. 물러서면(취소·Esc)
아무 일도 없습니다.

- 휴지통은 볼트 안 폴더 `_t-wiki.trash` 입니다. 지운 단위마다 칸(`<id>/원래이름`)을 하나 두고,
  어디서 왔는지·언제 옮겼는지는 `_index.json` 에 적습니다. 브라우저 저장소를 비워도 남고,
  다른 편집기로도 꺼낼 수 있습니다.
- **트리·검색·백링크·동기화 어디에도 나오지 않습니다.** 훑을 때 아예 건너뜁니다. 그래서 휴지통은
  이 컴퓨터에만 있고, 저장소에 올라가지 않습니다.
- 트리 맨 아래 **휴지통** 줄에 든 개수가 보이고, 누르면 지운 것마다 **원래 폴더와 옮긴 때**가
  나옵니다. **미리보기**를 누르면 그것이 무엇이었는지 그 자리에서 엿봅니다 — 글은 앞 4 KB 만,
  그림은 그림으로, 폴더는 안엣것 열두 개까지. 한 번에 한 줄만 펴 둡니다.
  **엿보는 칸의 키는 셋 다 같습니다**(220px). 내용에 따라 키가 달라지면 줄을 펼 때마다 목록이
  들썩입니다. 그림은 그 칸 안에 가운데로 앉고 제 비율대로 줄어듭니다 — 칸보다 작은 그림은
  늘리지 않고 그대로 둡니다. 예전에는 그림에 곧바로 키만 물렸는데, 이 칸이 세로로 쌓는
  칸(flex column)이라 그림이 가로로 늘어나 찌그러질 수 있었습니다.
  **고치지는 못합니다.** 편집까지 열어 주면 지운 것을 되살려 쓰는 길이 되어 복원과 뜻이 겹칩니다. **복원**은 원래 자리로 되돌리고, 그 자리에 다른 것이 생겼으면 덮을지 묻습니다.
  **완전 삭제**와 **휴지통 비우기**는 확인을 받고 없앱니다 — 여기 있는 것은 이 둘로만 없어집니다.
- **설정 → 일반 → 휴지통** 에서 "옮긴 지 오래된 것은 동기화할 때 저절로 비우기"를 켜면,
  GitHub 동기화가 돌 때마다 옮긴 지 정한 날수(기본 30일, 1~365)가 지난 것을 없앱니다.
  잣대는 **휴지통으로 옮긴 때**입니다. 비운 셈은 동기화 완료 알림에 함께 실립니다.
  기본은 꺼짐입니다 — 지우는 일을 기본으로 켤 수는 없습니다. 이 취향은 설정 파일에 담깁니다.

> 휴지통으로 옮기는 것도 저장소 쪽에서 보면 "로컬에서 사라짐" 입니다. **반대쪽에서도 지우기**가
> 꺼져 있으면(기본) 다음 동기화 때 저장소의 것이 다시 내려오고, 켜져 있으면 저장소에서도 지워집니다.
> 지우기 자체의 규칙이라 예전과 같습니다.

### 휴지통에 든 것이 언제까지 남는지

날짜만 적어 두면 "이게 오래된 건가" 를 머릿속에서 빼 봐야 압니다. 줄마다 한 마디를 덧붙이되,
**저절로 비우기를 켜 두었느냐에 따라 적는 것이 달라집니다.**

| 설정 | 줄에 적히는 것 | 칸 위 안내 |
| --- | --- | --- |
| 꺼짐(기본) | `(오늘 버림)` · `(버린 지 9일)` | 저절로 비우지는 않습니다 — 설정 → 일반 → 휴지통에서 켤 수 있습니다 |
| 켜짐 | `(21일 뒤 자동 삭제)` | 옮긴 지 **30일**이 지난 것은 동기화할 때 저절로 비웁니다 |
| 켜짐 · 날이 지남 | `(다음 동기화 때 삭제)` | 〃 |

- **켜져 있으면 남은 날, 꺼져 있으면 지난 날**입니다. 켜져 있을 때 지난 날을 적으면 옆의
  날짜에서 이미 어림할 수 있는 값을 되풀이하는 셈이고, 꺼져 있을 때 남은 날을 적으면 오지
  않을 날을 약속하는 것이 됩니다.
- 비우는 일은 **동기화가 돌 때** 일어나므로(`App` 이 동기화를 마친 자리에서 비웁니다),
  날이 지난 것은 며칠이 지났든 "다음 동기화 때" 라고 적습니다. 안내에도 "동기화할 때" 를
  빼지 않습니다 — 동기화를 쓰지 않는 사람에게 "30일 뒤 사라집니다" 는 거짓말입니다.
- 남은 날은 **올림**으로 셉니다. 내림하면 오늘내일 사라질 것이 "0일 뒤" 로 적혀 뜻이 흐려집니다.
  잣대는 비우는 쪽(`purgeTrashOlderThan`)과 같습니다 — 옮긴 지 날수가 지나면 없앱니다.
- 셈의 잣대인 "지금" 은 칸에 들어온 때로 잡되, **목록에 그보다 나중에 버린 것이 있으면 그
  때를 씁니다.** 한 번 잡아 두기만 했더니 이 칸을 열어 둔 채 다른 곳에서 파일을 지웠을 때
  갓 버린 것이 "31일 뒤" 로 적혔습니다. 그릴 때마다 시계를 읽으면 같은 화면이 두 번 다르게
  그려지고(`react(purity)`), effect 로 고쳐 넣으면 한 번 더 그리게 됩니다(`react(set-state-in-effect)`).
  목록에서 끌어내면 셈이 늘 같은 값으로 떨어지고 버리는 일마다 저절로 따라옵니다.

### 밖에서 바뀐 파일은 덮어쓰기 전에 묻습니다

브라우저는 파일이 바뀌었다고 알려 주지 않습니다. 같은 문서를 다른 편집기로 고치는 사이에
여기서 한 글자만 쳐도 자동 저장이 그 수정을 지워 버렸습니다. 이제 **쓰기 직전에 디스크의
수정 시각을 마지막으로 읽거나 쓴 시각과 견주고**, 다르면 멈추고 묻습니다.

- **밖의 내용 다시 읽기** — 편집기를 디스크의 글로 바꿉니다. 여기서 친 것은 사라집니다.
- **내 것으로 덮어쓰기** — 편집기의 글을 씁니다. 밖에서 고친 것은 사라집니다.
- **취소(Esc)** — 아무것도 쓰지 않고 편집을 이어갑니다. 같은 글로는 다시 묻지 않고,
  더 치면 새 글이므로 다시 묻습니다. 다른 문서로 떠날 때도 한 번 더 묻습니다.

물러서는 길은 늘 "아무것도 하지 않음" 입니다. 무언가를 잃는 선택은 이름 붙은 단추로만 둡니다.

### 동기화가 판단하는 방식

로컬 내용, 저장소 내용, **마지막으로 양쪽이 같았던 시점의 내용** 세 가지를 비교합니다(3-way).
견주는 값은 전부 **git blob SHA**, 즉 파일 내용에서 나온 해시입니다.
수정 시각을 보지 않으므로 시계 차이나 파일시스템 정밀도에 흔들리지 않습니다.

| 상황 | 결과 |
| --- | --- |
| 양쪽 해시가 같음 | 변경 없음 |
| 기준 해시 = 저장소 해시 | 로컬만 바뀐 것 → 커밋 |
| 기준 해시 = 로컬 해시 | 저장소만 바뀐 것 → 내려받기 |
| 기준 해시가 양쪽 어느 것과도 다름 | **충돌** — 설정한 정책대로 처리 |
| 기록은 있는데 한쪽에서 사라짐 | 삭제 전파 설정에 따라 삭제하거나 복원 |
| 사라진 자리의 내용이 새 경로에 그대로 있음 | **이름 바꾸기·이동**으로 보고 옛 경로를 정리 |

- **충돌 처리 방식** 기본값은 *양쪽 다 보존* 입니다.
  저장소 버전을 `문서 (저장소 사본 2026-08-28 1530).md` 로 로컬에 남기고,
  원래 자리에는 로컬 버전을 커밋합니다. 무엇도 잃지 않습니다.
- **삭제 전파** 는 기본으로 꺼져 있습니다. 켜기 전까지 삭제는 옮겨가지 않고,
  남아 있는 쪽에서 다시 복사해옵니다. 켜더라도 저장소 쪽은 커밋으로 남아 되돌릴 수 있습니다.
- 점으로 시작하는 파일과 폴더는 건너뜁니다.
- **이름을 바꾸거나 폴더를 옮기면** 내용 해시가 같은 것을 보고 이동으로 알아챕니다.
  삭제가 아니라 이동이므로 삭제 전파 설정과 무관하게 옛 경로를 정리합니다.
  다만 같은 내용의 파일이 여럿이면 어느 것이 어디로 갔는지 알 수 없으므로 이동으로 보지 않습니다.

### 커밋 방식

바뀐 파일이 몇 개든 **커밋 하나**로 묶입니다. blob → tree → commit → ref 순서로 만들고,
브랜치 이동은 force 없이 하므로 우리가 트리를 읽은 뒤 누군가 푸시했다면 거부됩니다.
남의 커밋을 덮어쓰는 일은 생기지 않습니다. 이때는 다시 미리보기를 실행하면 됩니다.

커밋 메시지는 자동으로 만들어집니다.

```
t-WiKi: 문서 3건, 삭제 1건

+ 회사/온보딩.md
+ 개발 환경.md
+ 회고/2026-08.md
- 임시 메모.md
```

## 무료 정적 호스팅

빌드 결과가 순수 정적 파일이고 클라이언트 라우팅도 쓰지 않아서, 리다이렉트 규칙 없이 어디든 올라갑니다.
GitHub 토큰 방식은 origin 을 미리 등록할 필요가 없으므로 **주소가 바뀌어도 상관없습니다.**
미리보기 URL 이든 localhost 든 그대로 동작합니다. 고를 때 볼 것은 **HTTPS 기본 제공** 정도입니다.

| 서비스 | 무료 한도 | 이 앱 기준 참고 |
| --- | --- | --- |
| **Cloudflare Pages** (추천) | 대역폭·요청 무제한, 빌드 월 500회 | 상업적 이용 제한이 없고 한도가 가장 넉넉합니다. 커스텀 도메인 무료. |
| **GitHub Pages** | 저장소 1GB, 대역폭 월 100GB(소프트 한도) | 가장 단순합니다. 하위 경로(`/저장소이름/`)로 서비스되므로 아래 `BASE_PATH` 설정이 필요합니다. |
| **Netlify** | 사용량 크레딧 방식으로 바뀌어 예전보다 빡빡함 | 폼·함수 같은 부가 기능이 필요할 때. 이 앱은 안 씁니다. |
| **Vercel** | Hobby 플랜은 **상업적 이용 불가** | 업무용 문서를 올릴 계획이라면 피하는 편이 안전합니다. |

정적 파일 성능은 넷 다 체감 차이가 없습니다. **Cloudflare Pages** 를 권합니다.

### Cloudflare Pages 에 올리기

Git 저장소를 연결하는 방식이 가장 편합니다.

1. 이 프로젝트를 GitHub 등에 올립니다.
2. Cloudflare 대시보드 → **Workers & Pages → Create → Pages → Connect to Git**
3. 빌드 설정
   - 빌드 명령: `npm run build`
   - 출력 디렉터리: `dist`
4. 배포가 끝나면 `https://프로젝트이름.pages.dev` 로 바로 쓸 수 있습니다. 추가 등록 절차는 없습니다.

CLI 로 바로 올리려면:

```bash
npm run build
npx wrangler pages deploy dist
```

### GitHub Pages 에 올리기

하위 경로로 서비스되므로 base 를 지정해 빌드해야 자산 경로가 맞습니다.

```bash
BASE_PATH=/저장소이름/ npm run build
```

`dist/` 를 `gh-pages` 브랜치에 올리거나 Actions 로 배포하면 `https://계정이름.github.io/저장소이름/` 에서 바로 열립니다.

> 앱을 올리는 저장소와 문서를 담는 저장소는 나눠 두는 편이 낫습니다.
> 같은 저장소를 쓰면 문서를 커밋할 때마다 사이트가 다시 빌드됩니다.

### Netlify / Vercel

빌드 명령 `npm run build`, 배포 디렉터리 `dist` 로 두면 그대로 동작합니다.

## 알려진 제약

- Chromium 계열 데스크톱 브라우저에서만 폴더를 열 수 있습니다.
- 브라우저 저장소를 비우면 폴더 접근 권한, 토큰, 동기화 기록이 사라집니다.
  문서 자체는 로컬 폴더와 저장소에 그대로 있으므로 다시 지정하면 됩니다.
  이때 기준 해시가 없어 내용이 다른 파일은 충돌로 잡히지만, 같은 파일은 자동으로 넘어갑니다.
- 토큰이 브라우저에 남아 있습니다(봉해서 두지만 같은 브라우저에서는 풀립니다).
  범위를 좁힌 fine-grained 토큰을 쓰고 만료일을 정해 두세요.
- 지난 결과는 이 브라우저가 돌린 회차만 압니다. 다른 기기에서 돌린 것은
  **자세히 보기** 로 저장소의 커밋 목록에서 봅니다.
- 저장소가 매우 크면 트리 응답이 잘릴 수 있습니다. 그때는 하위 폴더를 지정해 범위를 좁혀야 합니다.
