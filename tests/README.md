# 시험

```bash
npm test              # 전부
npm test -- vault     # 이름에 그 말이 든 묶음만
```

앱이 떠 있지 않으면 `run.mjs` 가 띄우고 끝나면 내립니다. 개발 중에 띄워 둔 것이 있으면
그대로 씁니다. 다른 자리에 띄웠다면 `APP_URL=http://localhost:4173 npm test`.

## 무엇이 어디에

| | |
| --- | --- |
| `run.mjs` | 묶음을 찾아 돌리고 결과를 모읍니다 |
| `mock-fs.js` | 브라우저에 심는 인메모리 File System Access 목 (폴더 고르기와 저장 창). 볼트 안 파일을 되읽는 `__vaultText` 도 여기 있습니다 |
| `github-mock.mjs` | 가짜 GitHub Git Data API |
| `suites/*.mjs` | 진짜 크롬을 띄워 화면을 만지는 묶음 |
| `suites/*.mts` | 브라우저 없이 함수만 보는 순수 로직 묶음 |

화면 갈무리는 `tests/shots/`, 내려받은 파일은 `tests/downloads/` 에 쌓이고 둘 다 저장소에
올리지 않습니다.

## 새 묶음을 더할 때

`suites/` 에 파일 하나를 두면 `run.mjs` 가 알아서 찾습니다. 기존 묶음 하나를 열어
그대로 본떠 쓰는 편이 빠릅니다. 규칙은 두 가지뿐입니다.

- 실패한 줄은 `FAIL` 로 시작하게 찍습니다. 달리는 쪽에서 그 줄만 추려 보여 줍니다.
- 실패가 하나라도 있으면 `process.exitCode = 1`.

## 미리 알아 둘 함정

지금까지 실제로 걸려 넘어진 것들입니다.

**목이 매기는 blob 이름은 진짜 git 방식이어야 합니다.** `sha1("blob <길이>\0" + 바이트)`.
아무 번호나 붙이면 앱이 로컬에서 계산한 해시와 절대 같아지지 않아, 내용이 그대로여도 늘
"바뀌었다" 로 잡힙니다. 그러면 "이미 저장소와 같습니다" 를 시험할 수 없습니다.
한 번 이걸로 앱 버그인 줄 알고 한참 헤맸습니다.

**목 폴더는 새로고침하면 새로 생깁니다.** 브라우저 저장소는 살아남지만 폴더 안 내용은
사라집니다. 그래서 파일에 적어 두는 것(즐겨찾기 같은)이 새로고침을 견디는지는 여기서
확인할 수 없습니다. 대신 폴더를 닫았다 다시 열어 봅니다.

**저장해 둔 폴더 손잡이는 메서드를 잃습니다.** 구조화 복제는 함수를 옮기지 않으므로,
IndexedDB 에서 꺼낸 목 손잡이에는 `isSameEntry` 가 없습니다. 그래서 이 시험대에서는
새로고침 뒤 폴더 복원이 실패하고 늘 "폴더 열기" 를 눌러야 합니다. 진짜 브라우저에서는
손잡이가 온전하므로, **복원 경로는 여기서 확인할 수 없습니다.**

**겹침은 네모 넷을 다 봐야 합니다.** 위아래만 견주면 옆 칸에 있는 것까지 겹친다고
잘못 셉니다. 눌리는지까지 보려면 `document.elementFromPoint` 로 그 자리에 무엇이 있는지
물어보는 편이 확실합니다.

**시험용 오피스 파일은 지어 씁니다.** `office-fixtures.mjs` 가 엑셀은 SheetJS 로,
워드는 파이썬 zipfile 로 규격에 맞춰 만듭니다. 이진 파일을 저장소에 넣어 두면 무엇이
들었는지 아무도 열어 보지 못합니다. 워드에서 목록을 살리려면 `numbering.xml` 까지
넣어야 합니다. 없으면 그냥 문단으로 나옵니다.

**CSP 는 조용히 깨집니다.** 막힌 것을 콘솔에서만 찾으면 놓칩니다.
`securitypolicyviolation` 사건을 창에 모아 두고 마지막에 셉니다. 그리고 그림이
막혔는지는 `src` 로 알 수 없습니다 — 주소는 막혀도 그대로 붙어 있으므로
`naturalWidth` 로 정말 그려졌는지 봅니다.

**끄는 동안의 움직임은 사건을 지어 보냅니다.** `dragTo` 는 집었다 놓는 두 걸음만
흉내 내므로, 끝에 손을 대고 기다리는 동안 일어나는 일은 볼 수 없습니다. 그럴 때는
`new DragEvent('dragover', { clientY })` 를 그 자리에 그대로 보냅니다.

**끌어 놓기는 `dragTo` 로 흉내 냅니다.** 마우스를 손으로 움직이면 HTML5 끌기가
일어나지 않습니다. 어느 쪽에 놓았는지까지 보려면 `targetPosition` 으로 줄의 위·아래
절반을 짚어야 합니다. 가운데에 놓으면 앞뒤 어느 쪽인지 가려지지 않습니다.

**메뉴 이름이 단추 글자와 겹치면 시험이 엉뚱한 것을 누릅니다.** 설정 왼쪽 갈래를
'지금 동기화' 로 적었더니 `button:has-text("지금 동기화")` 가 그 메뉴를 눌러, 정작
동기화는 돌지 않았습니다. 그래서 '동기화 실행' 으로 적어 두었습니다.

**글자로 단추를 찾지 마세요.** 아이콘만 남은 단추가 많습니다. `[aria-label="…"]` 로 찾습니다.

**파일 고르기 칸이 여럿입니다.** 첨부용 칸도 `.json` 을 받으므로 `accept` 로 고르면
엉뚱한 쪽을 집습니다. `#settings-bundle`, `#add-files` 처럼 id 로 짚습니다.
고르기 창 자체는 자동화로 열 수 없으니 단추를 누르지 말고 칸에 곧바로 얹습니다.
`accept` 는 플레이라이트가 지키지 않으므로, 걸러 주는지는 그 값을 직접 읽어 봅니다.

**백 건을 쌓으려고 백 번 돌리지 마세요.** IndexedDB (`keyval-store` 의 `keyval`)에
`mdwiki:sync-history` 를 직접 채워 넣고, 그다음 한 회차가 넘치는 것을 버리는지만 봅니다.
한계는 쌓을 때가 아니라 더할 때 걸리므로 채워 넣은 직후가 아니라 한 번 더 돌린 뒤에 셉니다.

**창 발치에 붙인 단추는 자리를 재야 압니다.** 목록 안에 있어도 `isVisible` 은 참입니다.
그 칸의 네모가 창의 네모 안에 드는지 견주어야 굴려 내려가야 닿는 것을 잡아냅니다.

**여백은 그 칸의 바깥에서 재세요.** 안쪽에 붙인 여백은 그 칸의 아래 끝을 함께
밀어내므로, 칸을 기준으로 재면 빈 자리가 있어도 없는 것으로 보입니다.
안에 든 마지막 줄에서 재야 드러납니다.

**접힌 폴더 안은 트리에 그려지지 않습니다.** 그 안의 줄을 만지려면 폴더를 먼저 폅니다.
폴더 줄을 누르는 것으로는 펴지지 않습니다(고르기만 합니다). 앞의 꺾쇠를 눌러야 합니다 —
`.tree-row:has-text("첨부") .tree-caret`.

**글꼴은 이름만 보면 속습니다.** 벌에 이름이 걸려 있어도 그 벌에 한글이 없으면 다른
글꼴로 그려집니다. 한글만으로 된 글의 폭을 재서 견줍니다. 띄어쓰기를 넣으면 빈칸이
라틴 벌에서 와 폭이 조금 달라지므로, 견줄 글에는 넣지 않습니다.
`document.fonts.check` 는 없는 이름에도 참을 내놓아 쓰지 않습니다.

**저장 창은 이름을 정하는 순간 빈 파일을 만듭니다.** 그 뒤에 물러서면 껍데기만 남습니다.
목도 그렇게 흉내 내므로, "물러서면 파일이 생기지 않는다" 가 아니라
"내용이 쓰이지 않는다" 를 봅니다. 저장 창 자체는 `window.showSaveFilePicker` 를
갈아끼워 흉내 내고, `__saveInto` 로 볼트 안·밖을, `__saveCancel` 로 창을 닫는 경우를 만듭니다.

## 여기서 확인할 수 없는 것

- 폴더 자동 복원 (위 참고)
- 진짜 GitHub 과의 주고받기. 가짜 서버는 우리가 쓰는 만큼만 흉내 냅니다
- 파이어폭스·사파리. File System Access API 가 없어 앱이 아예 뜨지 않습니다
