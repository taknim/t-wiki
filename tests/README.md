# 시험

```bash
npm test              # 전부
npm test -- vault     # 이름에 그 말이 든 묶음만
```

앱이 떠 있지 않으면 `run.mjs` 가 띄우고 끝나면 내립니다. 개발 중에 띄워 둔 것이 있으면
그대로 씁니다. 다른 자리에 띄웠다면 `APP_URL=http://localhost:4173 npm test`.

## 무엇이 어디에

| | |
| --- | --- |
| `run.mjs` | 묶음을 찾아 돌리고 결과를 모읍니다 |
| `peek.js` | 브라우저 저장소를 들여다보는 손. 별표로만 나오는 토큰을 저장소에서 풀어 견줄 때 씁니다 |
| `mock-fs.js` | 브라우저에 심는 인메모리 File System Access 목 (폴더 고르기와 저장 창). 볼트 안 파일을 되읽는 `__vaultText` 도 여기 있습니다. `window.__permission = 'prompt'` 로 두면 권한이 없을 때처럼 읽기·쓰기가 막히고, `window.__restoreHandle = true` 면 새로 고침 뒤에도 저장해 둔 손잡이가 되살아납니다 |
| `github-mock.mjs` | 가짜 GitHub Git Data API |
| `suites/*.mjs` | 진짜 크롬을 띄워 화면을 만지는 묶음 |
| `suites/*.mts` | 브라우저 없이 함수만 보는 순수 로직 묶음 |

화면 갈무리는 `tests/shots/`, 내려받은 파일은 `tests/downloads/` 에 쌓이고 둘 다 저장소에
올리지 않습니다.

## 지금 있는 묶음

| 묶음 | 무엇을 지키는가 |
| --- | --- |
| `vaultscope` | **폴더마다 저장소 설정과 기준점이 갈리는지.** 갈리지 않으면 다른 폴더를 열고 동기화했을 때 저장소의 파일이 전부 지워집니다 |
| `twoorigins` | 도메인이 둘일 때. **저장소가 갈려 있어 한쪽에서 연 새 폴더가 다른 쪽 기준점을 물려받지 않는지** |
| `addfiles` | 파일 넣기. **밖에서 쓴 마크다운도 들어오는지**, 넣은 문서가 내용을 지닌 채 열리는지, 같은 이름이면 번호가 붙는지, 모르는 형식은 물리치는지 |
| `syncprogress` | 동기화 진행 창. **도는 동안 단추 아래에 덮개 없이 붙고 지금 옮기는 파일이 적히는지**, 막대와 셈이 보이는지, 지난 줄이 아래로 밀리는지, 끝나면 걷히는지, 좁은 화면에서도 화면 안에 드는지 |
| `favsync` | 즐겨찾기 동기화. **두 기기가 저마다 담은 채 동기화하면 한쪽이 사라지지 않고 합쳐지는지**, 사본이 생기지 않는지, 양쪽 파일이 같아지는지, 부딪히지 않을 때는 뺀 것이 저쪽에도 따라가는지 |
| `reconnect` | 새로 고침 뒤 "다시 열기". **권한을 다시 받은 뒤에 즐겨찾기 파일이 들어오는지**(손잡이가 붙자마자 읽으면 권한이 없어 비어 보였습니다) |
| `leave` | 떠나기 전 묻기와 옮길 폴더 창. **폴더를 열어 둔 채 새로 고침하면 묻고 취소하면 그대로인지**(열기 전에는 묻지 않는지), **옮길 폴더 창이 지금 자리를 가운데에 보이게 굴린 채 뜨는지** |
| `mobile` | 좁은 화면(390px, hover 없음). **옆줄이 닫힌 채 시작해 본문이 화면을 다 쓰는지**, 메뉴 단추로 열면 본문을 밀지 않고 덮개와 함께 서랍처럼 뜨는지, **문서를 고르면 닫히고 폴더를 고르면 열린 채인지**, 덮개·접기 단추로 닫히는지, **손을 얹을 수 없어도 고른 줄의 단추가 보이는지**, 말풍선이 뜨지 않는지, **단축키 목록이 화면 안에 다 들어오는지**, 설정 창의 왼쪽 메뉴가 감춰지는지, **나란히 보기에서 누운 손잡이로 위아래 몫을 끌고 자판으로도 정하는지**, **끌지 않고 옮기기 단추로 폴더를 골라 옮기는지**(제 자신·지금 자리는 막히는지), 넓게 펴면 예전처럼 서는지 |
| `shortcuts` | 전역 단축키. **⌘/ 와 단추로 목록이 단추 아래에 덮개 없이 뜨고 Esc·바깥 누르기로 닫히는지**, ⌘P 가 접힌 옆줄을 펴서 검색 칸으로 가는지, ⌘⇧D 가 새 문서 창을 여는지, ⌘⇧E 가 보기 모드를 돌리는지, ⌘, 가 설정을 여는지, **편집기의 ⌘B 는 그대로 서식인지**, ⌘⇧1·⌘⇧2 가 옆줄 탭을 고르고 **옮겨 간 목록에 자리를 주는지**, ⌘⇧B 가 옆줄을 접고 펴는지(편집기 안에서도), **⌘⇧K·⌘⇧Y 가 줄 번호·커서 위치를 켜고 끄며 알림을 띄우고 설정 확인란도 따라오는지**, **⌘⇧L 이 행·열을 물어 가고 미리보기만 볼 때는 알리기만 하는지**, **⌘⇧G 가 동기화를 돌리고 설정이 덜 됐으면 설정을 여는지**, **폴더 트리와 즐겨찾기를 ↑↓ 로 오가고 Enter 로 열고 →← 로 펴고 접는지**, **자판으로 들어오면 첫 줄이 아니라 열어 둔 줄에서 시작하는지**, 창이 좁은지 |
| `secret` | 액세스 토큰 봉하기. **저장소에 글자 그대로는 어디에도 없고 풀면 제 값인지**, 열쇠가 꺼낼 수 없는 AES-GCM 256 인지, 새로 고침 뒤에도 풀어서 요청에 싣는지, **값이 있으면 입력란 대신 별표와 변경 단추만 서는지**, 치다가 물러서면 쓰던 토큰으로 돌아가는지, **잘못된 토큰이면 알리고 값과 앞서 띄운 저장소 목록을 거두는지**, **글자 그대로 적혀 있던 옛 토큰을 읽는 김에 봉하는지** |
| `tasks` | 할 일 목록. **미리보기의 네모를 눌러 원문이 `[ ]` ↔ `[x]` 로 바뀌고 저장되는지**, 인용·번호 목록도 제 줄이 바뀌는지, **코드 블록 안의 것은 셈에서 빠지는지**, 앞머리가 달린 글도 자리가 맞는지 |
| `tree` | 폴더 트리의 누르기. **폴더는 처음 누르면 고르기만 하고 다시 눌러야 펴지는지**, 꺾쇠는 고르지 않고 펴고 접기만 하는지, 문서는 한 번에 열리는지, **처음 오면 폴더 탭이 앞자리에 펴져 있는지**, **옮기기 전에 어디서 어디로인지 묻고 취소하면 그대로인지**, **같은 이름이 있으면 덮을지 묻고 고른 대로 하는지**(파일·폴더 양쪽), **끝에 닿으면 저절로 굴러가고 손을 놓으면 멈추는지**, **숨어 있던 줄을 골라도 보이는 자리로 끌려오는지**, **아래 표시줄 경로에 폴더 이름이 붙고 눌러서 베껴지는지**, **폴더도 항목 수 · 크기 · 시각을 차례로 밝히고 손을 얹으면 짧게 알려 주는지** |
| `external` | 밖에서 바뀐 파일. **다른 편집기가 고친 파일에 자동 저장이 덮어쓰지 않고 묻는지**, 다시 읽기·덮어쓰기가 각각 제대로 되는지, **취소하면 쓰지 않고 같은 글로는 되풀이해 묻지 않는지**, 떠날 때도 묻는지 |
| `doctools` | 본문에 떠 있는 단추. **바탕만 비치고(82%) 글자는 흐려지지 않는지**, **목차·백링크가 표시줄이 아니라 글 옆에 뜨는지**, **펼친 칸이 화면의 25%(높은 화면에서는 400px) 를 넘지 않고 짧은 목록은 제 내용만큼만 서는지**, **울타리 안의 울타리를 닫는 것으로 세지 않는지**(코드 안 제목이 목차에 안 들고 뒤 제목이 남는지), 눌러 폈다 접히는지, 맨 위·맨 아래로 한 번에 가는지, 굴릴 것이 없으면 그 단추가 없는지, **굴림대가 자리를 먹어도 틈이 그대로인지**, **워드·엑셀에서도 위아래 단추가 나오는지**, **보기 모드를 바꿔도 남는지**, **편집 화면에서도 목차로 그 줄에 가는지**(앞머리가 달린 글까지), **부를 단추가 사라지면 펼친 칸도 접히는지**, **백링크 셈이 펼친 목록과 맞고 어느 폴더의 것인지 밝히는지** |
| `loading` | 폴더를 여는 동안. **읽는 중이라고 알리고 어디까지 왔는지 세는지**, 셈이 나아가는지, 다 읽으면 트리로 바뀌는지 (목 폴더에 뜸을 들여 느린 폴더를 흉내 냅니다), **다시 훑을 때 크기·시각이 그대로인 문서의 본문은 도로 읽지 않고 바뀐 것만 읽는지**, **읽는 동안에는 동기화 단추가 잠기고 단축키로 불러도 저장소에 아무 요청도 가지 않는지** |
| `favorites` | 즐겨찾기와 옆줄 탭. 담고 빼기, **폴더 안 파일에 적히고 트리에는 안 보이는지**, 이름을 바꾸거나 지울 때 따라오는지, **탭을 고르면 그 쪽만 보이는지**, 접힌 옆줄의 단추가 펴면서 그 탭으로 가는지, **끌어다 놓아 차례를 바꾸면 파일에도 그 차례로 적히는지**(걸러 본 채로 옮겨도 가려진 줄이 제자리인지), **담긴 줄은 손을 얹지 않아도 켜진 별 단추만 보이고 이름 앞에 별을 따로 찍지 않는지, 손을 얹어도 별의 자리(맨 끝)가 그대로인지**, **파일을 손으로 고쳐 저장하면 목록이 따라오는지** |
| `split` | 나란히 보기의 두 칸 몫. 끌어서 바뀌는지, 양끝(20~80%)에서 멈추는지, 두 번 누르기·자판·새로고침, **잡은 동안 뜨는 숫자가 화면에 그려진 몫과 같은지**, 마크다운과 글 첨부가 같은 몫을 쓰는지 |
| `resize` | 트리 너비 끌기. 양끝이 막히는지, 새로고침·접었다 펴기 뒤에도 지켜지는지, 자판으로도 되는지 |
| `freshvault` | **텅 빈 새 폴더를 이미 쓰던 저장소에 맞춰도 저장소가 비워지지 않는지.** 삭제 전파를 켠 채로 확인합니다 |
| `legacy` | 폴더별로 가르기 전의 한 벌짜리 설정이 **처음 보는 폴더에 딸려 들어가지 않는지** |
| `viewmode` | 보기 모드. **새로고침·폴더 바꾸기 뒤에도 보던 모드로 열리는지**, 폴더마다 갈리는지, 기억하기를 끄면 따라오지 않는지 |
| `commitlink` | 마지막 동기화 줄의 커밋 이름. **저장소에 실제로 올라간 커밋을 가리키는지**, 올릴 것이 없는 동기화가 지우지 않는지, 폴더마다 갈리는지 |

## 새 묶음을 더할 때

`suites/` 에 파일 하나를 두면 `run.mjs` 가 알아서 찾습니다. 기존 묶음 하나를 열어
그대로 본떠 쓰는 편이 빠릅니다. 규칙은 두 가지뿐입니다.

- 실패한 줄은 `FAIL` 로 시작하게 찍습니다. 달리는 쪽에서 그 줄만 추려 보여 줍니다.
- 실패가 하나라도 있으면 `process.exitCode = 1`.

## 미리 알아 둘 함정

지금까지 실제로 걸려 넘어진 것들입니다.

**떠 있는 굴림대는 자리를 먹지 않습니다.** 이 시험대(맥)에서는 `::-webkit-scrollbar`
를 손봐도 그대로라, 굴림대가 자리를 먹는 기계를 흉내 내려면 `scrollbar-gutter: stable`
을 얹어야 합니다. 그때만 `offsetWidth - clientWidth` 가 0 이 아니게 됩니다.

**부드럽게 굴러가는 것은 누르자마자 재면 가는 도중입니다.** 멈출 때까지 폴링하고
재세요. 긴 글은 몇 초씩 걸려, 기다림을 정해 두면 기계에 따라 걸립니다.

**목이 매기는 blob 이름은 진짜 git 방식이어야 합니다.** `sha1("blob <길이>\0" + 바이트)`.
아무 번호나 붙이면 앱이 로컬에서 계산한 해시와 절대 같아지지 않아, 내용이 그대로여도 늘
"바뀌었다" 로 잡힙니다. 그러면 "이미 저장소와 같습니다" 를 시험할 수 없습니다.
한 번 이걸로 앱 버그인 줄 알고 한참 헤맸습니다.

**목 폴더는 새로고침하면 새로 생깁니다.** 브라우저 저장소는 살아남지만 폴더 안 내용은
사라집니다. 그래서 파일에 적어 두는 것(즐겨찾기 같은)이 새로고침을 견디는지는 여기서
확인할 수 없습니다. 대신 폴더를 닫았다 다시 열어 봅니다.

**저장해 둔 폴더 손잡이는 메서드를 잃습니다.** 구조화 복제는 함수를 옮기지 않으므로,
IndexedDB 에서 꺼낸 목 손잡이에는 `isSameEntry` 가 없습니다. 그래서 이 시험대에서는
새로고침 뒤 폴더 복원이 실패하고 늘 "폴더 열기" 를 눌러야 합니다. 진짜 브라우저에서는
손잡이가 온전하므로, **복원 경로는 여기서 확인할 수 없습니다.**

**겹침은 네모 넷을 다 봐야 합니다.** 위아래만 견주면 옆 칸에 있는 것까지 겹친다고
잘못 셉니다. 눌리는지까지 보려면 `document.elementFromPoint` 로 그 자리에 무엇이 있는지
물어보는 편이 확실합니다.

**시험용 오피스 파일은 지어 씁니다.** `office-fixtures.mjs` 가 엑셀은 SheetJS 로,
워드는 파이썬 zipfile 로 규격에 맞춰 만듭니다. 이진 파일을 저장소에 넣어 두면 무엇이
들었는지 아무도 열어 보지 못합니다. 워드에서 목록을 살리려면 `numbering.xml` 까지
넣어야 합니다. 없으면 그냥 문단으로 나옵니다.

**CSP 는 조용히 깨집니다.** 막힌 것을 콘솔에서만 찾으면 놓칩니다.
`securitypolicyviolation` 사건을 창에 모아 두고 마지막에 셉니다. 그리고 그림이
막혔는지는 `src` 로 알 수 없습니다 — 주소는 막혀도 그대로 붙어 있으므로
`naturalWidth` 로 정말 그려졌는지 봅니다.

**끄는 동안의 움직임은 사건을 지어 보냅니다.** `dragTo` 는 집었다 놓는 두 걸음만
흉내 내므로, 끝에 손을 대고 기다리는 동안 일어나는 일은 볼 수 없습니다. 그럴 때는
`new DragEvent('dragover', { clientY })` 를 그 자리에 그대로 보냅니다.

**끌어 놓기는 `dragTo` 로 흉내 냅니다.** 마우스를 손으로 움직이면 HTML5 끌기가
일어나지 않습니다. 어느 쪽에 놓았는지까지 보려면 `targetPosition` 으로 줄의 위·아래
절반을 짚어야 합니다. 가운데에 놓으면 앞뒤 어느 쪽인지 가려지지 않습니다.

**목 폴더는 눈 깜짝할 새에 읽힙니다.** 읽는 동안의 화면을 보려면 `getFile` 에 뜸을
들여 느린 폴더를 흉내 내야 합니다. 그러지 않으면 볼 틈도 없이 트리가 나옵니다.

**폴더를 다시 연 직후에는 트리가 한 번 더 그려집니다.** 그 틈에 줄을 누르면 눌린 줄이
새 줄로 바뀌어 아무것도 열리지 않습니다. 열렸는지 보고 한 번 더 누르는 편이 낫습니다.

**`overflow: hidden` 은 굴릴 수 있는 칸을 만듭니다.** 눈에 보이는 굴림대만 없을 뿐이라,
`scrollIntoView` 가 그 칸까지 밀어 올립니다. 설정 창 모서리를 둥글게 하려고 hidden 을
걸었더니, 갈래로 뛸 때 창이 통째로 밀려 머리줄이 화면 밖으로 사라졌습니다.
자르기만 하고 굴리지는 못하게 하려면 `clip` 입니다. 그리고 이런 것은 넉넉한 창에서는
드러나지 않습니다. 좁은 창으로 줄여 놓고 봐야 합니다.

**이따금 걸리는 묶음은 시험대가 아니라 앱을 의심하세요.** viewmode 가 열에 넷쯤
걸렸는데, 기다림을 늘려도 그대로였습니다. 복원 자리에 한 줄 찍어 보니 `cancelled: true`
— 색인이 도착하면서 효과가 다시 돌아 앞서 시작한 복원이 취소되고, 다시 돈 쪽은
"이미 복원했다" 는 표에 걸려 그대로 물러나고 있었습니다. 시험이 아니라 앱의 흠이었습니다.

**메뉴 이름이 단추 글자와 겹치면 시험이 엉뚱한 것을 누릅니다.** 설정 왼쪽 갈래를
'지금 동기화' 로 적었더니 `button:has-text("지금 동기화")` 가 그 메뉴를 눌러, 정작
동기화는 돌지 않았습니다. 그래서 '동기화 실행' 으로 적어 두었습니다.

**글자로 단추를 찾지 마세요.** 아이콘만 남은 단추가 많습니다. `[aria-label="…"]` 로 찾습니다.

**파일 고르기 칸이 여럿입니다.** 첨부용 칸도 `.json` 을 받으므로 `accept` 로 고르면
엉뚱한 쪽을 집습니다. `#settings-bundle`, `#add-files` 처럼 id 로 짚습니다.
고르기 창 자체는 자동화로 열 수 없으니 단추를 누르지 말고 칸에 곧바로 얹습니다.
`accept` 는 플레이라이트가 지키지 않으므로, 걸러 주는지는 그 값을 직접 읽어 봅니다.

**백 건을 쌓으려고 백 번 돌리지 마세요.** IndexedDB (`keyval-store` 의 `keyval`)에
`mdwiki:sync-history` 를 직접 채워 넣고, 그다음 한 회차가 넘치는 것을 버리는지만 봅니다.
한계는 쌓을 때가 아니라 더할 때 걸리므로 채워 넣은 직후가 아니라 한 번 더 돌린 뒤에 셉니다.

**창 발치에 붙인 단추는 자리를 재야 압니다.** 목록 안에 있어도 `isVisible` 은 참입니다.
그 칸의 네모가 창의 네모 안에 드는지 견주어야 굴려 내려가야 닿는 것을 잡아냅니다.

**여백은 그 칸의 바깥에서 재세요.** 안쪽에 붙인 여백은 그 칸의 아래 끝을 함께
밀어내므로, 칸을 기준으로 재면 빈 자리가 있어도 없는 것으로 보입니다.
안에 든 마지막 줄에서 재야 드러납니다.

**접힌 폴더 안은 트리에 그려지지 않습니다.** 그 안의 줄을 만지려면 폴더를 먼저 폅니다.
폴더 줄을 누르는 것으로는 펴지지 않습니다(고르기만 합니다). 앞의 꺾쇠를 눌러야 합니다 —
`.tree-row:has-text("첨부") .tree-caret`.

**글꼴은 이름만 보면 속습니다.** 벌에 이름이 걸려 있어도 그 벌에 한글이 없으면 다른
글꼴로 그려집니다. 한글만으로 된 글의 폭을 재서 견줍니다. 띄어쓰기를 넣으면 빈칸이
라틴 벌에서 와 폭이 조금 달라지므로, 견줄 글에는 넣지 않습니다.
`document.fonts.check` 는 없는 이름에도 참을 내놓아 쓰지 않습니다.

**저장 창은 이름을 정하는 순간 빈 파일을 만듭니다.** 그 뒤에 물러서면 껍데기만 남습니다.
목도 그렇게 흉내 내므로, "물러서면 파일이 생기지 않는다" 가 아니라
"내용이 쓰이지 않는다" 를 봅니다. 저장 창 자체는 `window.showSaveFilePicker` 를
갈아끼워 흉내 내고, `__saveInto` 로 볼트 안·밖을, `__saveCancel` 로 창을 닫는 경우를 만듭니다.

## 여기서 확인할 수 없는 것

- 폴더 자동 복원 (위 참고)
- 진짜 GitHub 과의 주고받기. 가짜 서버는 우리가 쓰는 만큼만 흉내 냅니다
- 파이어폭스·사파리. File System Access API 가 없어 앱이 아예 뜨지 않습니다
